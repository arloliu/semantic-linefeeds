# v0.9d — A Corpus of Real Agent Repairs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** build the population v0.9b's widening is scored against.

The existing corpus measures whether a finding is correct.
This one measures what happens next:
given a `fused` finding delivered the way the hook delivers it,
what does a repairing agent do with the line,
and is what it did right.

**Architecture:** a second corpus beside the first, sharing its instrument rather than copying it.
The draw, the batching, the three blind passes, the adjudication,
and the frozen reporting rules are the ones `tests/corpus/` already runs.
Three things are new.
The unit is a window rather than a boundary.
A rewrite is normalized into something two rewrites can be compared as.
And the admission test a later widening must pass is written down before any of it is measured.

Two changes land outside the new directory.
The core gains a name for every class that withholds a suggestion,
so a stratum cannot drift from the branch it stands for.
The holdout ledger gains a binding between a freeze, a round, and a sample,
because it does not have one today and the repair round will need it.

**Tech Stack:** Python 3.9+ stdlib only for the core;
pytest for the gate;
the three model-family CLIs for the passes, as in every previous round.

**Decisions this plan implements:**
[ADR-0003](../../decisions/0003-precision-measured-against-labels.md),
[ADR-0007](../../decisions/0007-fixability-classes.md),
[ADR-0008](../../decisions/0008-a-holdout-is-spent-by-being-opened.md).

| 0.95 | 10 |

## Governing constraint: this slice measures, and measuring is all it does

The umbrella states one ordering that must not be inverted:
a class is admitted on scored evidence, never on judgment.
That ordering decides what belongs here and what does not.

**This plan changes no predicate.**
Task 2's core change is a refactor with no behavioural difference,
proven by a golden holding every fused fixture's complete suggestion value.
Whether `_fused_suggestion` fires, and what it produces when it does, is exactly what it was.

**This plan draws no repair holdout.**
The ledger binds a predicate digest,
and v0.9b's widened predicate does not exist yet.
A bundle drawn now would be frozen against the predicate whose successor it is meant to test.
The sequencing is the one v0.4.2 used for its recall repair:
written first, frozen and scored afterwards, by a different session.

**Therefore no class is admissible on what this plan delivers.**
That belongs in the acceptance criteria and not only here.
What this plan delivers is the instrument, a calibration population, a preregistered admission test,
and the floors that test will be run against.

**The ledger does not enforce what this plan needs, and Task 8 fixes it.**
`freeze_predicate` records a predicate digest, a manifest digest, and an intent, and nothing more
(`tests/corpus_harness.py:815-833`).
`require_predicate_freeze` accepts any earlier record naming the current predicate
(`tests/corpus_harness.py:835-853`),
`draw.py` writes no freeze identity into the sample it produces
(`tests/corpus/holdout/draw.py:49-98`),
and `seal.py` binds the current predicate to a sample that already exists
(`tests/corpus/holdout/seal.py:125-175`).
So this sequence is not refused today:
freeze A, draw and label a sample, tune to B after reading it, append a freeze for B, seal against B.
Nothing in the tooling notices.
That hole predates this plan and would be inherited by the repair round,
so Task 8 closes it before the round that would walk into it.

**This slice's session must not touch v0.9b.**
The standing constraint is that the session tuning a predicate does not label the round that scores it.
Reading 250 repairs is exactly the memory that constraint exists to keep out of a tuning session.

**No path here writes a user's file.**
Hook-side mutation stays where the umbrella left it.

### One objection to answer before a reviewer files it

The draw samples detector **findings**, not labeled true violations,
and ADR-0003 forbids a denominator built from detector output.

This is not that.
ADR-0003's rule protects a recall claim:
candidates drawn from current findings exclude every violation the detector already misses,
which makes the miss unfalsifiable.
The quantity here is conditional on delivery by construction.
"Given that a finding reached the agent, was the repair right"
has the detector's firing in its condition rather than in its denominator,
and a finding the detector never raises has no repair to measure.

The existing corpus measures whether the condition is true.
This one measures what follows from it.
Both are needed, and neither substitutes for the other.

## Group 1 — What is being measured, fixed before anything is measured

### Task 1: Preregister the admission test

**Class:** design

**Files:**
- Modify: `tests/corpus/manifest.json`, `tests/corpus/manifest.lock`
- Modify: `tests/corpus_harness.py`
- Modify: `tests/test_corpus_manifest.py`

This task exists because of an ordering mistake worth naming.
A floor stated after its labels are read is not a gate,
and a plan that runs its round first and states its bar afterwards has stated no bar at all.
So the bar goes first, before a single repair has been elicited.

What must be fixed here, and what may be computed later, are different things.
The **rule** is fixed now.
The **number** the rule produces is computed in Task 11 from the calibration round,
which is how every recall floor in this manifest was already derived
and is not the same as choosing a number once the answer is visible.

Preregister, in `manifest.json` under `repair_admission`:

**The denominator.**
A unit is scored when it has a settled acceptable set and is not ambiguous.
Ambiguous units are excluded from rates and retained as cases,
as the label corpus already treats them.

**The candidate statistic.**
For a candidate class, the rate is the fraction of its scored units
whose machine repair lands in the acceptable set.

**The baseline.**
The shipped class — the units no class withholds — scored the same way,
and scored **through the same two-line composition** every candidate is scored through.
Today's suggestion replaces the anchor alone (`scripts/check_linefeeds.py:1326-1329`),
so scoring it as-is against a two-line window would read as though it deleted the line below.
It is composed with the untouched lower line first, and Task 3 defines that composition.
A baseline measured through the old shape would be a bar for a shape nobody is proposing.

**The test, which is non-inferiority and not a threshold.**
The floor is the lower bound of the Wilson-95 interval around the baseline rate.
A candidate is admissible only when **its own lower Wilson bound** clears that floor.
Comparing a candidate's point estimate against a floor is what the existing recall gate does
(`tests/corpus_harness.py:642-673`),
and it is the wrong comparison here:
against a baseline of 36 units, a materially worse candidate clears the baseline's lower bound easily.
Both sides are held to the same end of their intervals, or the comparison means nothing.

**The fallback, stated now because it cannot be derived later.**
If the baseline carries fewer than `min_true_violations` scored units,
or its interval is wider than `max_interval_half_width`,
no floor can be derived from it,
and the absolute floor is **0.90**, with the same lower-bound test.
That number is stated here, blind, with no repair labels in existence.
It is high on purpose:
an automatic repair runs without a reader,
and the alternative to a strict bar is not a lower bar but no widening at all.

**Three zero-tolerance conditions, which are conditions and not rates.**
Any one of them refuses a class however well it scores:

- a machine repair that does not preserve the prose,
- a machine repair that changes a carrier, as Task 3 defines carrier validity,
- a machine repair that fires on a unit whose acceptable set is the original.
  Automatically repairing a line that should have been left alone is the worst outcome this tool can produce.

- [ ] **Step 1:** Write `repair_admission` into `manifest.json`, every clause above, and repin the lock.
- [ ] **Step 2:** `REPAIR_ADMISSION` frozen in `tests/corpus_harness.py`,
      checked against the manifest the way `_reporting_problems` checks `REPORTING`,
      so the preregistered rule cannot be edited into agreement with a result.
- [ ] **Step 3:** A test that the manifest's `repair_admission` matches the frozen constant,
      and that changing either alone turns the suite red.
- [ ] **Step 4:** A test that a floor recorded for a baseline with no reportable rate is a defect.
- [ ] **Step 5:** A test with a candidate whose point rate clears the floor
      and whose lower bound does not, asserting refusal.

**Acceptance:** the admission test is committed before any repair exists,
and no later task can weaken it without turning a named test red.

### Task 2: The repair classes, and their names outlive the predicate

**Class:** contract

**Files:**
- Modify: `scripts/check_linefeeds.py`
- Modify: `tests/test_diagnostics.py`, `tests/test_schema.py`
- Modify: `tests/corpus/repairs/measure.py`

A stratum is only as trustworthy as its definition,
and there are three separate problems with taking `_fused_suggestion`'s refusals as strata unchanged.

**A refusal is not a repair class.**
`_fused_suggestion` asks whether the character before the gap is `!` or `?`
(`scripts/check_linefeeds.py:1312-1318`),
which answers "no" for a period boundary and for a `!` behind a closing quote alike.
`FUSED_RE` allows closing quotes, brackets, parens, and emphasis between the punctuation and the gap
(`scripts/check_linefeeds.py:350-355`),
so one refusal covers a period boundary and a delimiter-reconstruction boundary.
Those are different repairs carrying different risks,
and a marginal rate over their union cannot admit either.
The same holds for the gap test, which merges tabs with repeated spaces,
and for the prefix test, which merges list markers with docstrings and block comments.

**A class must outlive the predicate that refuses it.**
If v0.9b admits periods, `_fused_withholding` stops reporting `terminator_period`,
and the stratum the holdout was drawn on disappears from the taxonomy that named it.
So the class list is its own constant, not a derived view of the current refusals.

**Two of the classes are decided outside the function.**
`carrier_stripped` is decided at the call site (`scripts/check_linefeeds.py:1375-1387,1428-1432`),
and the harness must not reconstruct it —
that is the drift this task exists to prevent.

The classes, named rather than numbered so a widening cannot renumber them:

| class | when it applies |
|---|---|
| `carriage_return` | a `\r` in the raw line |
| `many_boundaries` | `FUSED_RE` matches more than once |
| `protected_span` | a backtick, `<`, or `>` anywhere in the prose |
| `prose_not_unique` | the prose does not sit in the raw line exactly once |
| `gap_multiple_spaces` | the gap is two or more spaces |
| `gap_tab` | the gap holds a tab |
| `gap_other_whitespace` | any other gap that is not one ASCII space |
| `terminator_period` | the sentence punctuation is `.` |
| `closing_delimiter` | a closing quote, bracket, paren, or emphasis stands between the punctuation and the gap |
| `prefix_list_marker` | the carrier prefix is rejected and begins with a list marker |
| `prefix_other` | the carrier prefix is rejected for any other reason |
| `tail_rejected` | anything but whitespace follows the prose in the raw line |
| `carrier_stripped` | a trailing suppression carrier came off the line before it was judged |

The prefix and tail classes are evaluated **only when the prose sits in the raw line exactly once**.
The shipped function stops at `prose_not_unique` and never reaches them
(`scripts/check_linefeeds.py:1310-1311`),
and testing them against an arbitrary occurrence would invent a class the code never had.

`ws` is not guarded, and the reason is worth writing down.
`FUSED_RE` requires a non-empty whitespace run after the punctuation,
and `text` comes from that match,
so `re.search(r"\s+", text)` cannot return `None` and `ws.start()` cannot be zero.

- [ ] **Step 1:** `WITHHOLDING_CLASSES` and `_fused_withholding(prose, raw, match)`
      returning every class that applies, in declaration order.
      Rewrite `_fused_suggestion` over it: a suggestion is produced when the tuple is empty.
- [ ] **Step 2:** The call site contributes `carrier_stripped` to the tuple rather than short-circuiting on it.
- [ ] **Step 3:** `diagnose(text, path, spans=None, withholding=False)`.
      With the flag set, each `fused` diagnostic gains `withheld_by`.
      Default off, so `to_schema` is unchanged and no consumer sees a new key,

- [ ] **Step 4:** Prove the refactor is a refactor.
      A committed golden holds the **complete suggestion value** for every fused fixture,
      not merely whether the key is present.
      `tests/test_diagnostics.py:296-343` already asserts exact suggestion dictionaries;
      the golden extends that to the whole fixture tree.
- [ ] **Step 5:** One test per class, each triggering that class and asserting the full tuple.
      `carriage_return` and `prose_not_unique` have no natural fixture:
      construct them against `_fused_withholding` directly,
      and say in a comment that no extractor path reaches either today.
- [ ] **Step 6:** A test that `prefix_*` and `tail_rejected` are absent whenever `prose_not_unique` is present.
- [ ] **Step 7:** Mutation: deleting any class turns a named test red.
- [ ] **Step 8:** Rewrite `measure.py` to import the classes from the core,

**Acceptance:** the suggestion behaviour is unchanged, value for value;

### Task 3: The window, the carrier, and what a repair is once normalized

**Class:** design

**Files:**
- Modify: `tests/corpus_harness.py`
- Create: `tests/test_corpus_repairs.py`

This is the task the rest of the plan rests on,
because it decides what a repair is as a comparable object.

**The window is one or two lines.**
A suggestion today replaces the anchor alone,
and the measurement says that is the wrong window for most of the population:
6,167 of 9,316 findings in the dominant class carry a `wrap` on the same line,
and v0.9a shipped the rule that the rejoin comes before the split.
So the window is the anchor and the line beneath it —
the same window v0.9b's successor to `_fused_suggestion` will replace.

A `fused` finding on the **last prose line of a paragraph or file** has no line beneath it.
`diagnose` applies `FUSED_RE` to every prose line independently and requires no successor
(`scripts/check_linefeeds.py:1391-1432`),
while the boundary instrument only builds units from adjacent pairs
(`tests/corpus_harness.py:263-274`).
Reusing that shape unchanged would silently drop those findings from the population.
The window therefore has an explicit one-line form,
and a test asserts a last-line finding produces one.

**The carrier is extracted by the core, not matched by a regex.**
`_SUGGESTION_PREFIX_RE` validates an already-separated prefix; it does not find one
(`scripts/check_linefeeds.py:1281-1292`).
It also rejects list markers deliberately,
while the Markdown extractor strips a list marker from prose and keeps it in raw
(`scripts/check_linefeeds.py:919-925`),
which is exactly the `prefix_list_marker` class this corpus has 576 units of.
Normalizing with that regex would be unable to score one of the classes it exists to score.

So normalization does not parse carriers at all.
It **applies the replacement to the file's lines in memory and re-extracts prose through `prose_stream`**,
the same path the detector reads.
Whatever the extractor calls prose is prose, for the original and for the repair alike,
and the two corpora cannot disagree about where a line's content begins.

**A repair normalizes to three facts.**

```python
def normalize_repair(unit, replacement, text, path):
    """Reduce a rewrite to what makes two rewrites comparable.

    The replacement is spliced into the file's lines and re-extracted through `prose_stream`,
    so a list marker, an indent, and a comment leader are handled by the extractor
    rather than by a second opinion about what a carrier looks like.

    `preserving` says the prose is the same text, differing only in where it breaks.
    `breaks`     says where it now breaks, as offsets into the window's joined prose.
    `carriers`   says which line leaders the repair used, for the carrier rule below.
    """
```

`preserving` compares the joined prose with internal whitespace runs collapsed to one space.
`breaks` is meaningful only when `preserving` holds,
and is computed from the re-extracted per-line prose lengths.
The original window is itself a point in this space:
a two-line window's original is one break at the length of the anchor's prose,
and a one-line window's original is no breaks at all.
So **"leave it alone" is an answer the corpus can represent**,
which matters because a finding whose right answer is to change nothing is an outcome here rather than a hole.

**The carrier rule, stated rather than assumed.**
A repair is carrier-valid when every line it produces carries the leader the extractor would require there:
a split inside a comment repeats the comment leader,
a split inside a list item continues with the item's indent and no second marker,
and a rejoin drops the leader of the line it absorbed.
Nothing else is carrier-valid.
A repair that preserves the prose and breaks this rule is a defect,
it is recorded on the unit,
and Task 1 makes it a zero-tolerance condition for admission.

**Composing the shipped suggestion.**
`_fused_suggestion` returns two lines replacing the anchor.
To score it in this space, those two lines are spliced in place of the anchor
and the untouched lower line is kept.
A test asserts the lower line is byte-identical after composition,
because a composition that dropped it would score the baseline as catastrophic and the bar as trivial.

- [ ] **Step 1:** `repair_window(record, text, path)`, one-line and two-line forms.
- [ ] **Step 2:** `normalize_repair` as above, over `prose_stream` rather than over a prefix regex.
- [ ] **Step 3:** `carrier_valid(unit, replacement)` implementing the carrier rule.
- [ ] **Step 4:** `compose_shipped_suggestion(unit, suggestion)` and its byte-identity test.
- [ ] **Step 5:** Tests covering, at minimum:
      a last-line finding; a repair touching only the lower line; a three-line repair;
      a bulleted item and an ordered item with indented continuations;
      an anchor and a lower line with different leaders;
      a split that must repeat the anchor's leader;
      a rejoin that must drop one;
      an unchanged window; a reworded window; a window with a clause dropped;
      and a prose-preserving repair that corrupts a carrier.
- [ ] **Step 6:** Mutation: dropping the whitespace collapse,
      comparing before re-extraction,
      or accepting a carrier-invalid repair each turns a named test red.

**Acceptance:** every shape in the measured population is representable,
a rewrite that loses a word never reports `preserving`,
a rewrite that mangles a leader never reports carrier-valid,
and doing nothing is an answer.

### Task 4: The acceptable set, and the resolution that completes it

**Class:** design

**Files:**
- Modify: `tests/corpus_harness.py`
- Modify: `tests/test_corpus_repairs.py`
- Create: `tests/corpus/repairs/REPAIRING.md`

A label has three values and a repair does not.
Three things follow, and together they change the rule rather than reusing `resolution`.

**A repair has more than one correct answer.**
A long fused line can be split at either of two real clause boundaries,
and both results are correct prose.
So the settled outcome is a **set of acceptable break vectors**,
and the question a later score asks is whether the machine's answer is in that set.

**The set must be complete, not merely observed.**
Three repairers agreeing on one valid boundary does not make a second valid boundary wrong.
If unanimity settled the set to the one vector three passes happened to choose,
a candidate splitting at the other real boundary would score as an error,
and the rate would measure coincidence of taste rather than correctness.
So completeness is elicited rather than inferred:
**each pass returns its own repair and every other break it judges acceptable**,
and the acceptable set is the union of what three independent passes were willing to accept.

**A pass can fail to answer rather than answer differently.**
A rewrite that loses a clause is not a vote for a different break;
it is evidence about what repairing this line costs.

The rule:

```python
def repair_resolution(passes):
    """Settle three normalized repairs into an outcome, or refer them.

    Only passes that preserve the prose and keep the carriers valid vote.
    A unit settles when the three accepted sets agree and at least two passes voted.
    Anything else goes to a maintainer:
    a disagreement about where a line may be cut is the defect source ADR-0008 names,
    and it is the same question a widening asks.
    """
```

- the accepted sets agree, with at least two voters: `settled`,
  and the acceptable set is that agreed set.
- otherwise `adjudicated`, and a maintainer states the acceptable set,
  which may hold vectors no pass proposed, and may hold the original.
- a maintainer may record `ambiguous`,
  meaning the rule does not settle what this line should become.
  Ambiguous units leave the denominator and stay as cases.

A non-preserving or carrier-invalid pass is recorded on the unit as a defect with its normalized diff,
whether or not it changed the outcome.

**Nothing may enlarge an acceptable set after a machine suggestion has been read.**
Promotion is the only place a suggestion is read, and it runs last.
A test enforces the ordering rather than a comment asking for it.

`REPAIRING.md` is the procedure a pass is given,
and it stands to this corpus as `LABELING.md` stands to the other one.
It says what a repairer sees, what it must return, and what never to do.
It does **not** say how three passes are combined,
for the reason `LABELING.md` gives for the same omission:
a pass that knows which answer survives a disagreement answers a different question.

- [ ] **Step 1:** `repair_resolution` and its tests, one per branch.
- [ ] **Step 2:** The acceptable-set representation,
      with tests that the original vector is expressible and that a set may hold more than one vector.
- [ ] **Step 3:** A test that a unit where all three passes chose vector A
      while all three also accepted vector B settles to a set holding both,
      and that a candidate producing B scores correct.
- [ ] **Step 4:** A test that promotion cannot add a vector after reading `suggestion_today`.
- [ ] **Step 5:** `REPAIRING.md`, pointing at `SKILL.md` as the normative rule the way `LABELING.md` does.
- [ ] **Step 6:** Mutation: letting a non-preserving or carrier-invalid pass vote turns a named test red.

**Acceptance:** the acceptable set is what three independent repairers were willing to accept,
not what they happened to pick;
a lost clause never counts as a vote;
and no set grows after the machine has spoken.

### Task 5: The draw

**Class:** design

The population is every `fused` finding the detector raises on the calibration sources.
Not every boundary, as in the label corpus:
a repair exists only where a finding was delivered, which is the conditional this corpus measures.

**Stratification is by membership, and one unit belongs to several levels.**
`level_of` returns one scalar level per dimension (`tests/corpus_harness.py:476-510`),
which cannot express a line refused by three classes at once.
The draw needs a second form:
a declared level universe, membership rather than a single value,
and a quota per class that a unit may count toward more than one of.

Two kinds of quota, because a widening asks two questions:

- **marginal**, one per declared class, so every class can carry its own rate;
- **exact set**, for the sets a candidate would actually activate on —
  starting with the empty set, which is the shipped class
  and the baseline the whole admission test rests on.

`quota_shortfalls` derives its levels from the values it sees
(`tests/corpus_harness.py:523-555`),
so a declared class with no population is invisible to it.
The new form takes its universe from `WITHHOLDING_CLASSES` and reports an empty class as a shortfall,
because "no units" and "not asked for" must not look the same in the output.

```python
BASE = 200
SEED = "repairs-1"
PER_CLASS = 40
```

Forty is the third measurement and nothing else:
the smallest number that still prints a rate near 0.70 under the frozen half-width rule.
The empty-set quota takes everything the population has, which the measurement puts at about 36.

- [ ] **Step 1:** `repair_population(source, root)` in the harness,
      enumerating `fused` findings with their windows, class vectors, and covariates,
      calling `diagnose(..., withholding=True)`.
      This is the one place in the drawing path that may read the detector, and it reads no suggestion.
- [ ] **Step 2:** A membership-quota draw beside `draw_corpus`,
      with a declared universe and per-class and per-exact-set quotas.
- [ ] **Step 3:** Shortfall reporting over the declared universe,
      so an empty class appears as a line rather than as an absence.
- [ ] **Step 4:** `draw.py` over the three calibration sources, writing `sample.json`
      with `population`, `seed`, `base`, quotas, and every shortfall.
- [ ] **Step 5:** A test that a base containing no empty-set units
      still reports the empty-set quota as a shortfall.
- [ ] **Step 6:** A test that a unit carrying two classes counts toward both marginals and its exact set.
- [ ] **Step 7:** A leakage test: monkeypatch `_fused_suggestion` to return a unique string
      and assert it appears nowhere in the drawn sample.

**Acceptance:** the draw is deterministic from its seed,
every non-empty class reaches its quota or reports why it could not,
the shipped class is drawn rather than left to chance,
and no suggestion reaches the sample.

### Task 6: The elicitation batch

**Class:** design

**Files:**
- Create: `tests/corpus/repairs/batch.py`
- Modify: `tests/corpus_harness.py`
- Modify: `tests/test_corpus_repairs.py`

A pass must see what a repairing agent sees, minus the answer.
Being precise about the "minus" is the point of this task.

**What a pass is shown is a blinded hook body, and the plan says so rather than claiming otherwise.**
`format_findings` renders the report body and never reads a suggestion
(`scripts/check_linefeeds.py:1548-1557,1570-1630`).
But `deliver` is what a host actually sends,
and it appends a suggested-replacement block for any finding carrying one,
followed by the judgment and suppression notes
(`scripts/check_linefeeds.py:1943-1975`).
So the batch is `format_findings` output and not `deliver` output,
and that is a deliberate redaction rather than a reproduction.
It follows that the elicited non-preserving rate is a statement about agents given a blinded body,
not a statement about agents given complete hook feedback.
Task 12 records that limit where a reader of the results will find it.

**The rendering is pinned exactly**, because each of these changes the text:

- every finding on the anchor line is included, `fused` and any co-anchored `wrap` or `long`,
  since ADR-0021 is the reason a `wrap` travels with the block at all
  and the repair it invites is the rejoin this corpus measures;
- `snippet=False`, so the report says "line N" rather than "line N of your edit";
- `skill_hint=True`, matching what a host sends when the skill is installed.

**What it must never show:** the suggestion, another pass's answer, or the class names.

The answer shape:

```json
[{"id": "<unit id>", "lines": ["..."], "also_acceptable": [["..."], ["..."]]}]
```

`lines` is the repair the pass would make, as full replacement lines for the window.
`also_acceptable` is every other rewrite it judges correct, and may be empty.
Returning the window unchanged in `lines` is how a pass says the right answer is to change nothing;
no separate flag is offered,
because a flag would be an easier answer than the others and would collect the undecided.

Order is derived from the pass's name, as `labeling_batches` already does.

- [ ] **Step 1:** `repair_batches`, mirroring `labeling_batches`, size 15, name-derived order.
- [ ] **Step 2:** `batch.py` rendering the header, `SKILL.md`'s rule, `REPAIRING.md`'s procedure, and the units.
- [ ] **Step 3:** A test that a unit's rendered report equals `format_findings` output
      for the pinned finding selection and arguments, so the two cannot drift.
- [ ] **Step 4:** A test over a fused line carrying `wrap` and `long` as well,
      asserting all three reach the batch.
- [ ] **Step 5:** A leakage test with a monkeypatched suggestion secret,
      asserting it appears in no rendered batch.
- [ ] **Step 6:** A test that no class name from `WITHHOLDING_CLASSES` appears in a rendered batch.

**Acceptance:** a batch is reproducible from the sample and the pass name alone,
it carries the hook's own words for the part it carries,
and the plan is honest about the part it withholds.

### Task 8: Bind a freeze to its round and its sample

**Class:** contract

**Files:**
- Modify: `tests/corpus_harness.py`
- Modify: `tests/corpus/holdout/freeze.py`, `tests/corpus/holdout/draw.py`, `tests/corpus/holdout/seal.py`
- Modify: `tests/test_corpus_freeze.py`, `tests/test_corpus_seal.py`

This closes a hole in the existing protocol,
and it is in this plan because the repair round is the next thing that would fall into it.

Today a freeze names a predicate and an intent and nothing else
(`tests/corpus_harness.py:815-833`),
`require_predicate_freeze` accepts any earlier record with the current digest
(`tests/corpus_harness.py:835-853`),
the sample records no freeze identity (`tests/corpus/holdout/draw.py:49-98`),
and sealing binds whatever predicate is current to a sample that already exists
(`tests/corpus/holdout/seal.py:125-175`).
So: freeze A, draw, label, tune to B, freeze B, seal against B.
Every step is permitted, and the bundle looks correctly sealed afterwards.
The ordering the whole protocol exists to enforce is kept by care, and care is not a mechanism.

The repair:

- a freeze record carries a **round** and a **record id**,
- `freeze_predicate` refuses a second pre-draw freeze for a round that already has one,
- the draw writes the freeze's record id and predicate digest into `sample.json`,
- the seal requires the sample's recorded freeze to exist,
  to name this round, and to name the predicate being sealed,
- and a freeze for one round never authorizes another.

Rounds 1 to 3 wrote freeze records with no round.
**Those records are not edited.**
The ledger is append-only and accepted records stand as written.
The requirement applies to records written from here on,
and the validator says so in the message it refuses with,
so a reader of a legacy record is told why it is exempt rather than left to infer it.

- [ ] **Step 1:** Extend the freeze record with `round` and `id`, and refuse a duplicate pre-draw freeze.
- [ ] **Step 2:** `require_predicate_freeze(round)` matching on predicate **and** round,
      accepting a legacy record only for rounds 1 to 3 and naming that exemption when it does.
- [ ] **Step 3:** The draw writes the freeze identity into the sample.
- [ ] **Step 4:** The seal requires an exact match against the sample's recorded identity.
- [ ] **Step 5:** A test reproducing the full sequence —
      freeze A, draw, refreeze B, seal — and asserting refusal.
- [ ] **Step 6:** Tests that a round-3 freeze does not authorize round 4,
      and that editing or removing the sample's freeze identity prevents sealing.
- [ ] **Step 7:** A test that the three sealed rounds still open,
      because a protocol repair that invalidates the evidence already gathered is not a repair.

**Acceptance:** the post-draw refreeze sequence is refused by tooling rather than by care,
and the existing bundles are untouched.

### Task 9: The manifest section and its validator

**Class:** contract

**Files:**
- Modify: `tests/corpus/manifest.json`, `tests/corpus/manifest.lock`
- Modify: `tests/corpus_harness.py`
- Modify: `tests/test_corpus_manifest.py`

The repair records live in the same manifest as the label records,
under a `repairs` section beside `units`.
One manifest, one lock, one digest to repin:
splitting them would let one move without the other noticing.

A repair record:

| field | what it holds |
|---|---|
| `id` | `<source>:<path>:<line>#repair` |
| `source`, `path`, `lines`, `frame` | as the label records carry them |
| `window` | the one or two raw lines, and which form it is |
| `withheld_by` | the class vector from `diagnose(..., withholding=True)` |
| `covariates` | the co-occurring `wrap`, the language, and the exact class set |
| `passes` | per pass: the raw reply, the normalized break vector, `preserving`, `carrier_valid`, and the accepted set |
| `outcome` | `settled`, `adjudicated`, or `ambiguous` |
| `acceptable` | the set of correct break vectors |
| `adjudication` | the maintainer's reason, when there is one |
| `suggestion_today` | the composed shipped suggestion, whether it is acceptable, and its `preserving` and `carrier_valid` flags |

`repair_problems(record)` joins `manifest_problems`,
naming what is wrong by unit rather than counting it,
in the idiom `_unit_problems` sets.
It must reject at least:
an empty `acceptable` on a settled unit;
a voting pass with no break vector;
a pass marked `preserving` with no `carrier_valid` recorded;
a class not in `WITHHOLDING_CLASSES`;
a `suggestion_today` recorded for a unit the shipped predicate withholds;
and a repair floor keyed to a round the manifest does not declare.

- [ ] **Step 1:** The section, the record shape, and `SECTIONS` extended to require it.
- [ ] **Step 2:** `repair_problems`, one message per defect class, each with a test.
- [ ] **Step 3:** A mutation test per rejected defect class.
- [ ] **Step 4:** Repin `manifest.lock` with a line saying the repair corpus was added.

**Acceptance:** the validator names the unit,
and every defect class it rejects has a test that dies if the check is removed.
