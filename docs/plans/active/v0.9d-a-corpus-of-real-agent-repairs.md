# v0.9d — A Corpus of Real Agent Repairs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** build the population v0.9b's widening is scored against.

The existing corpus measures whether a finding is correct.
This one measures what happens next:
given a `fused` finding delivered the way the hook delivers it,
what does a repairing agent do with the line,
and is what it did right.

**Architecture:** a second corpus beside the first, sharing its instrument rather than copying it.
The draw, the batching, the three blind passes, the resolution, the adjudication,
and the reporting rules are the ones `tests/corpus/` already runs.
What is new is the unit — a two-line window rather than a boundary —
and the resolution rule that decides when two rewrites are the same rewrite.
One change lands in the core:
the reasons a suggestion is withheld become a named list the harness reads,
so a stratum cannot drift from the branch it stands for.

**Tech Stack:** Python 3.9+ stdlib only for the core;
pytest for the gate;
the three model-family CLIs for the passes, as in every previous round.

**Decisions this plan implements:**
[ADR-0003](../../decisions/0003-precision-measured-against-labels.md),
[ADR-0007](../../decisions/0007-fixability-classes.md),
[ADR-0008](../../decisions/0008-a-holdout-is-spent-by-being-opened.md).

## What was measured before this plan was written

Three measurements shaped it,
and each is reproducible from the commands beside it.

### The wild population is too thin to score a widening

Every commit in this repository was walked,
and a finding whose anchor line does not survive into the child blob was counted as a repair event.

| | events |
|---|---|
| `wrap` | 116 |
| `fused` | at most 10 |

Over 261 commits, non-test Markdown, Python, Go, and TypeScript.
"At most" is the honest word for the `fused` number:
the probe counts any anchor line that stopped existing,
so a deletion or an unrelated rewrite is counted alongside a real repair.

v0.9b widens the automatic class for `fused`.
Ten events cannot score that, and a live capture path starts lower still, at zero.
**So the population is elicited rather than captured**, and the reason is this number.
The capture path the umbrella scopes is deferred by Task 10 with this measurement recorded as its reason.

### What withholds a suggestion today, and how often

`_fused_suggestion` refuses in eight places and its call site refuses in a ninth.
Each refusal is a class a widening could admit,
so each is a stratum this corpus must be able to report on.
Counted over this repository's own prose,
attributing each finding to the first refusal it hits:

| stratum | n | of which also carry a `wrap` |
|---|---|---|
| terminator is a period | 1659 | 1004 |
| a protected span sits on the line | 461 | 206 |
| the gap is not one ASCII space | 430 | 282 |
| more than one boundary on the line | 99 | 38 |
| **suggested today** | 19 | 12 |
| the carrier prefix is rejected | 1 | 0 |
| a carriage return in the raw line | 0 | 0 |
| the prose is not unique in the raw line | 0 | 0 |
| the carrier tail is rejected | 0 | 0 |

Three observations the plan turns on.

The class that ships today is 19 of 2,669 findings,
so `!` and `?` are close to a rounding error against what a widening would reach.

Three strata are empty here and will likely stay near-empty on any corpus.
Task 9 states the consequence rather than leaving it to be discovered:
a stratum with no reportable rate is not admissible.

The co-occurring `wrap` is not a corner.
It is 61% of the dominant stratum in this repository,

A repair unit that cannot express "pull the line below up, then split"

## Governing constraint: this slice measures, and measuring is all it does

The umbrella states one ordering that must not be inverted:
a class is admitted on scored evidence, never on judgment.
That ordering decides what belongs here and what does not.

**This plan changes no predicate.**
The one core change, Task 1, is a refactor with no behavioural difference,
proven by an identity test over the existing fixtures.
Whether `_fused_suggestion` fires is exactly what it was.

**This plan draws no repair holdout.**
The ledger binds a predicate digest,
and v0.9b's widened predicate does not exist yet.
A bundle drawn now would be frozen against the predicate it is meant to test the successor of,
or would sit unspent while the predicate moved underneath it.
`seal.py` already refuses both, and this plan does not work around it.
The sequencing is the one v0.4.2 used for its recall repair:
written first, frozen and scored afterwards, by a different session.

**Therefore admitting any class needs a repair holdout this plan does not draw.**
That sentence belongs in the acceptance criteria and not only here.
What this plan delivers is the instrument, a calibration population, and the floors —
the three things that make a later score mean something.

**This slice's session must not touch v0.9b.**
The standing constraint is that the session tuning a predicate does not label the round that scores it.
Reading 250 repairs is exactly the memory that constraint exists to keep out of a tuning session.

**No path here writes a file.**
Hook-side mutation stays where the umbrella left it.

### One objection to answer before a reviewer files it

The draw samples detector **findings**, not labeled true violations,
and ADR-0003 forbids a denominator built from detector output.

This is not that.
ADR-0003's rule protects a recall claim:
candidates drawn from current findings exclude every violation the detector already misses,
which makes the miss unfalsifiable.
The quantity here is conditional on delivery by construction.
"Given that a finding reached the agent, was the repair right"
has the detector's firing in its condition rather than in its denominator,
and a finding the detector never raises has no repair to measure.

The existing corpus measures whether the condition is true.
This one measures what follows from it.
Both are needed, and neither substitutes for the other.

### Task 1: The reasons a suggestion is withheld become a list the harness can read

**Class:** contract

**Files:**
- Modify: `scripts/check_linefeeds.py`
- Modify: `tests/test_diagnostics.py`

A stratum is only as trustworthy as its definition.
If the harness re-implements the eight refusals in `_fused_suggestion`,
the two copies drift, and the drift lands in the evidence a widening is admitted on.
v0.4.2 hit this exact shape with the licence cut and resolved it the same way:
one function, called from both sides, rather than a mirror maintained by care.

Extract the refusals into `_fused_withholding`, which returns every reason that applies:

```python
# Every reason a suggestion is withheld, in one place, because two of them are read from outside.
# The corpus stratifies on this vector, so a branch that exists only inside `_fused_suggestion`
# would be a class the evidence cannot see.
# All reasons are collected rather than short-circuited: each is a pure test over the two strings,
# and a widening admits one reason at a time, so it has to know which others still stand.
WITHHOLDING_REASONS = (
    "carriage_return",
    "many_boundaries",
    "protected_span",
    "prose_not_unique",
    "gap_not_one_space",
    "terminator_not_bang_or_query",
    "prefix_rejected",
    "tail_rejected",
)


def _fused_withholding(prose, raw, match):
    """Every reason this fused boundary gets no suggestion, in declaration order."""
    reasons = []
    if "\r" in raw:
        reasons.append("carriage_return")
    if len(list(FUSED_RE.finditer(prose))) != 1:
        reasons.append("many_boundaries")
    if "`" in prose or "<" in prose or ">" in prose:
        reasons.append("protected_span")
    if raw.count(prose) != 1:
        reasons.append("prose_not_unique")
    text = match.group(0)
    ws = re.search(r"\s+", text)
    if ws.group(0) != " ":
        reasons.append("gap_not_one_space")
    if text[ws.start() - 1] not in "!?":
        reasons.append("terminator_not_bang_or_query")
    idx = raw.find(prose)
    if idx >= 0:
        if not _SUGGESTION_PREFIX_RE.match(raw[:idx]):
            reasons.append("prefix_rejected")
        if not _SUGGESTION_TAIL_RE.match(raw[idx + len(prose) :]):
            reasons.append("tail_rejected")
    return tuple(reasons)
```

`_fused_suggestion` then reduces to the withholding test and the split it already performs.
The ninth reason is `carrier_stripped`, and it lives at the call site rather than in this function
because it is a property of how the line was read, not of the line.
The harness records it as a tenth field beside the vector.

- [ ] **Step 1:** Extract `_fused_withholding` and rewrite `_fused_suggestion` over it,
      with no change to what either produces.
- [ ] **Step 2:** Prove the refactor is a refactor.
      A test asserts that for every fixture under `tests/fixtures/` carrying a `fused` finding,
      the presence or absence of a `suggestion` key is what it was at `HEAD~1`.
      Capture the before-state as a committed golden rather than as a remembered number.
- [ ] **Step 3:** One test per reason, each triggering exactly that reason and no other,
      asserting the returned vector.
      `prose_not_unique` and `carriage_return` have no natural fixture,
      so construct them directly against `_fused_withholding`
      and say in a comment that no extractor path reaches either today.
- [ ] **Step 4:** Mutation: deleting any single reason from `WITHHOLDING_REASONS`
      or from the function turns a named test red.
      An unnamed total moving is not enough.

**Acceptance:** the suggestion behaviour is byte-identical to before,
the reason vector is importable, and each reason has a test that dies when the reason does.

### Task 2: The repair window, and what a repair is once it is normalized

**Class:** design

**Files:**
- Modify: `tests/corpus_harness.py`
- Create: `tests/test_corpus_repairs.py`

This is the task the rest of the plan rests on,
because it decides what a repair is as a comparable object.

**The window is two lines, not one.**
A suggestion today replaces the anchor alone.
The measured co-occurrence says that is the wrong window for most of the population:
61% of the dominant stratum in this repository, and 34% over the pinned evidence base,
carry a `wrap` on the same line,
and v0.9a shipped the rule that the rejoin comes before the split.
The correct repair for those moves text across the boundary between the anchor and the line below.

So a repair unit spans the anchor line and the line beneath it —
the same two-line window v0.9b's successor to `_fused_suggestion` will replace.
A pure anchor split and a rejoin-then-split are then the same kind of object,
and one rule scores whatever shape v0.9b produces.

**A repair normalizes to two facts.**

```python
def normalize_repair(window, replacement):
    """Reduce a rewrite to the two facts that make two rewrites comparable.

    `window` is the unit's two raw lines; `replacement` is what the pass returned.
    `preserving` says nothing was added, dropped, or reworded.
    `breaks` says where the prose was cut, as offsets into the window's joined prose.

    A repair that is not preserving casts no vote about where the break belongs:
    it is a defect record, and the offsets it would imply are not meaningful.
    """
```

The steps it performs:

1. Strip each line's carrier — the indent and comment leader `_SUGGESTION_PREFIX_RE` already describes —
   from both the window and the replacement.
2. Join each side's prose with a single space, and collapse internal whitespace runs to one space.
3. `preserving` is whether the two joined strings are then equal.
4. `breaks` is the set of offsets into the window's joined prose
   where the replacement introduced a line break,
   computed by walking the replacement's per-line lengths.
   It is meaningful only when `preserving` holds.
5. `carrier_changed` is whether the replacement's leaders differ from the window's.
   It is recorded separately from `preserving`,
   because changing `//` to `#` is a different defect from losing a clause.

The original itself has one break, at the length of the anchor's prose.
That matters:

- a repair that only splits the anchor yields two breaks,
- a repair that rejoins and splits elsewhere yields one break at a different offset,
- and **a repair that changes nothing yields exactly the original break**.

The third is the useful one.
"Leave this line alone" is expressible in the same space as every other answer,
so a finding whose right answer is to change nothing is a measurable outcome here rather than a hole.

- [ ] **Step 1:** `repair_window(record, root)` returning the two raw lines and their joined prose,
      built from the same file read `records_for` uses so the two corpora cannot disagree about a line.
- [ ] **Step 2:** `normalize_repair(window, replacement)` as above.
- [ ] **Step 3:** Tests covering, at minimum:
      an anchor-only split; a rejoin-then-split; an unchanged window;
      a reworded window; a window with a clause dropped;
      a window whose leaders changed; a replacement of one line, three lines, and zero lines.
- [ ] **Step 4:** Prove `preserving` by mutation.
      Dropping the whitespace collapse, or comparing before stripping the carrier,
      each turns a named test red.

**Acceptance:** two rewrites that differ only in whitespace normalize equal,
a rewrite that loses a word never reports `preserving`,
and doing nothing is representable.

### Task 3: The resolution rule for repairs

**Class:** design

**Files:**
- Modify: `tests/corpus_harness.py`
- Modify: `tests/test_corpus_repairs.py`
- Create: `tests/corpus/repairs/REPAIRING.md`

A label has three values and a repair does not.
Two things follow, and both change the rule rather than reusing `resolution`.

**A repair has more than one correct answer.**
A long fused line can be split at either of two real clause boundaries,
and both results are correct prose.
So the settled outcome of a unit is not one repair but a **set of acceptable break vectors**,
and the question a later score asks is whether the machine's answer is in that set.

**A pass can fail to answer rather than answer differently.**
A rewrite that loses a clause is not a vote for a different break;
it is evidence about what repairing this line costs.

The rule:

```python
def repair_resolution(passes):
    """Settle three normalized repairs into an outcome, or refer them.

    Only preserving passes vote.
    Unanimity among the voters settles; anything else goes to a maintainer,
    because a disagreement about where a line splits is the defect source ADR-0008 names
    and resolving it silently throws that away.
    Fewer than two voters is a referral regardless of what the voters said.
    """
```

- unanimous among preserving passes, with at least two of them: `settled`,
  and the acceptable set is that one vector.
- otherwise: `adjudicated`, and a maintainer states the acceptable set,
  which may hold more than one vector and may hold the original.
- a maintainer may also record `ambiguous`,
  meaning the rule does not settle what this line should become.
  Ambiguous units are excluded from rates and retained as cases,
  exactly as the label corpus treats them.

A non-preserving pass is recorded on the unit as a defect with its normalized diff,
whether or not it changed the outcome.

`REPAIRING.md` is the procedure a pass is given,
and it stands to this corpus as `LABELING.md` stands to the other one.
It says what a repairer sees, what it must return, and what never to do.
It does **not** say how three passes are combined,
for the reason `LABELING.md` gives for the same omission:
a pass that knows which answer survives a disagreement answers a different question.

- [ ] **Step 1:** `repair_resolution` and its tests, one per branch.
- [ ] **Step 2:** The acceptable-set representation, and a test that the original vector is expressible in it.
- [ ] **Step 3:** `REPAIRING.md`, pointing at `SKILL.md` as the normative rule the way `LABELING.md` does.
- [ ] **Step 4:** Mutation: letting a non-preserving pass vote turns a named test red.

**Acceptance:** three identical rewrites settle,
two-against-one refers rather than resolving to the majority,
and a lost clause never counts as a vote.

### Task 4: The draw

**Class:** design

**Files:**
- Create: `tests/corpus/repairs/draw.py`
- Modify: `tests/corpus_harness.py`

The population is every `fused` finding the detector raises on the calibration sources.
Not every boundary, as in the label corpus:
a repair exists only where a finding was delivered, which is the conditional this corpus measures.

The strata are Task 1's reason vector, plus one more:

| dimension | levels |
|---|---|
| withholding reason | the nine reasons, as a vector |
| co-occurring `wrap` | whether the anchor line also carries one |
| language | `go`, `markdown`, and whatever else the sources hold |

Stratifying on a vector needs a rule,
since a line refused for three reasons belongs to three levels.
The draw quotas on **each reason independently**,
so a unit can count toward more than one level,
and the report prints the marginal per reason.
That is what a widening needs:
it admits one reason at a time and has to know which others still stand on the same line.

```python
BASE = 200
SEED = "repairs-1"
PER_LEVEL = 40
```

Forty per level is the third measurement above and nothing else:
it is the smallest number that still prints a rate near 0.70 under the frozen half-width rule.

- [ ] **Step 1:** `repair_population(source, root)` in the harness,
      enumerating `fused` findings with their windows, reason vectors, and covariates.
      It calls `diagnose`, which is the one place in this corpus's drawing path that may.
      The suggestion is not read here, and a test asserts the drawn sample carries no suggestion field.
- [ ] **Step 2:** `draw.py` over the calibration sources, reusing `draw_corpus` and `quota_shortfalls`.
- [ ] **Step 3:** Report what the quotas could not buy, as the label corpus's draw does.
      An empty stratum must be visible in the output rather than absent from it.
- [ ] **Step 4:** Record the drawn sample as `tests/corpus/repairs/sample.json`,
      with `population`, `seed`, `base`, and the quota spec, so a reviewer redraws.

**Acceptance:** the draw is deterministic from its seed,
every non-empty stratum reaches 40 or reports why it could not,
and the sample carries no detector suggestion.

### Task 5: The elicitation batch

**Class:** design

**Files:**
- Create: `tests/corpus/repairs/batch.py`

A pass must see what a repairing agent sees and nothing more.
That is not a paraphrase of the hook's report — it is the report,
rendered by `format_findings` from the finding itself,
so a change to the delivered wording changes what the corpus measured instead of quietly diverging from it.

What one unit shows:

- the file's lines around the window, marked so the two editable lines are unambiguous,
- the `format_findings` output for that line, verbatim,
- nothing else.

What it must never show:
the suggestion, another pass's answer, or the fact that a reason vector exists.

The answer shape:

```json
[{"id": "<unit id>", "lines": ["<first line>", "<second line>"]}]
```

with `"lines"` holding as many lines as the repair needs, and the same two lines back
when the right answer is to change nothing.
An explicit `"unchanged": true` is **not** offered:
it would be an easier answer than the others and would attract the undecided,
and the same meaning is already expressible by returning the window.

Order is derived from the pass's name, as `labeling_batches` already does,
so fatigue and drift do not line up across passes.

- [ ] **Step 1:** `repair_batches` in the harness, mirroring `labeling_batches`,
      with the same size-15 batching and name-derived order.
- [ ] **Step 2:** `batch.py` rendering the header, the rule, `REPAIRING.md`'s procedure, and the units.
- [ ] **Step 3:** A test that the rendered report for a unit equals `format_findings` output for it,
      so the two can never drift.
- [ ] **Step 4:** A test that no rendered batch contains the string `suggestion`
      or any of the reason names.

**Acceptance:** a batch is reproducible from the sample and the pass name alone,
and it carries the hook's own words rather than a description of them.

### Task 6: Collect, adjudicate, promote

**Class:** mechanical

**Files:**
- Create: `tests/corpus/repairs/collect.py`
- Create: `tests/corpus/repairs/adjudicate.py`
- Create: `tests/corpus/repairs/promote.py`

These three mirror the label corpus's scripts closely enough that the differences are the whole content.

`collect.py` normalizes every pass through Task 2, resolves through Task 3,
and reports per stratum: settled, referred, ambiguous, and non-preserving.
The non-preserving count is a headline rather than a footnote —
it is the rate at which a competent agent damages a line while repairing it,
and it is the number that most directly bounds what any automatic class may be trusted with.

`adjudicate.py` carries referrals to the maintainer,
showing every pass's normalized break vector against the window,
and taking back an acceptable set with a reason.

`promote.py` writes settled units into `manifest.json`,
and it is the **only** place the machine suggestion is read.
For each unit it records what `_fused_suggestion` produces today,
whether that suggestion is in the acceptable set,
and the reason vector that withheld it where it produced nothing.

- [ ] **Step 1:** `collect.py`, with the per-stratum marginal `collect.py` already prints for labels.
- [ ] **Step 2:** `adjudicate.py`, using the multiple-choice grouping this repository's adjudications use.
- [ ] **Step 3:** `promote.py`, recording the suggestion and its verdict at promotion time only.
- [ ] **Step 4:** A test that promotion refuses a unit whose passes were never collected,
      and refuses a referral that has no adjudication.

**Acceptance:** a reviewer can rerun all three from the committed `.out` files
and reach the same manifest bytes.

## Group 3 — What a widening must clear

### Task 9: The floors, and the round-4 requirement

**Class:** design

**Files:**
- Modify: `tests/corpus/manifest.json`, `tests/corpus/manifest.lock`
- Modify: `tests/corpus/README.md`

A floor is a prediction stated before the round that answers it.
This task states the floors v0.9b's widening must clear,
and it is the last thing this plan does before it stops.

**The bar is what the shipped class already achieves.**
A widening asks to be trusted with a class the tool does not touch today.
The honest bar is therefore not an invented number
but the rate the class that already ships attains on the same instrument:
`suggestion_today` in the acceptable set,
measured over the `!`/`?` stratum on calibration.
A class that performs worse than the one already trusted has not earned the same trust.

The floor for a candidate class is then the lower end of the Wilson interval around that shipped-class rate,
rounded down to two places —
the same construction `holdout_basis` uses for every recall floor in this manifest.

Two conditions ride alongside the rate, and neither is a rate:

- **Zero non-preserving suggestions.**
  A suggestion that drops or rewords text is not a lower score; it is a defect,
  and one is enough to refuse a class.
- **Zero suggestions on a unit whose acceptable set is the original.**
  Automatically repairing a line that should have been left alone is the worst outcome this tool can produce,
  and it is exactly what the precision constraint exists to prevent.

**A stratum with no reportable rate is not admissible.**
Three of the nine reasons were empty on the measurement above,
and a stratum that cannot print a rate under the frozen half-width rule cannot clear a floor.
Saying so here closes the escape hatch:
without this line, "no rate, so no floor" would admit a class on judgment,
which is the failure the whole ordering exists to prevent.

**And the floors are cleared on a holdout this plan does not draw.**
The calibration numbers above are a description of the shipped predicate,
not a score that admits anything.
ADR-0008's third decision is unambiguous:
a repair that adds findings cannot be scored on the corpus it was tuned against,
and a widening adds suggestions.

So this task also states what round 4 must be, without drawing it:

- three sources, none of the nine already in the manifest,
- the same composition split: one self-authored, one third-party code, one third-party Markdown,
- qualified by `qualify.py` on line-length distribution alone, as round 2 and 3 were,
- drawn only after the widened predicate is frozen in the ledger,
- and drawn, labeled, and sealed by a session that did not tune that predicate.

- [ ] **Step 1:** Compute the shipped class's rate on calibration, with its interval.
