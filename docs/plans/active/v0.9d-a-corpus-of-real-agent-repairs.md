# v0.9d — A Corpus of Real Agent Repairs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** build the population v0.9b's widening is scored against.

The existing corpus measures whether a finding is correct.
This one measures what happens next:
given a `fused` finding delivered the way the hook delivers it,
what does a repairing agent do with the line,
and is what it did right.

**Architecture:** a second corpus beside the first, sharing its instrument rather than copying it.
The batching, the three blind passes, the adjudication,
and the frozen reporting rules are the ones `tests/corpus/` already runs.
Four things are new.
The sampling stratum is an exact set of withholding classes rather than one level per dimension.
The unit is a window rather than a boundary.
A rewrite is normalized into something two rewrites can be compared as.
And the bar a later widening must clear is written down before any of it is measured.

Two changes land outside the new directory.
The core gains a name for every class that withholds a suggestion,
and exposes the judged line the detector actually read,
so neither a stratum nor a normalizer can drift from the code it stands for.
The holdout ledger gains a binding between a freeze, a round, and a sample,
because it has none today and the repair round would inherit its absence.

**Tech Stack:** Python 3.9+ stdlib only for the core;
pytest for the gate;
the three model-family CLIs for the passes, as in every previous round.

**Decisions this plan implements:**
[ADR-0003](../../decisions/0003-precision-measured-against-labels.md),
[ADR-0007](../../decisions/0007-fixability-classes.md),
[ADR-0008](../../decisions/0008-a-holdout-is-spent-by-being-opened.md).

### What the frozen reporting rules cost

`REPORTING` fixes a Wilson-95 interval and a 15-point maximum half-width
(`tests/corpus_harness.py:112-118`).
The smallest stratum that can carry a rate, and what a floor costs at each size:

| n | rate needed for a Wilson lower bound of 0.80 |
|---|---|
| 34 | 32 of 34, a point rate of 0.941 |
| 40 | 37 of 40, a point rate of 0.925 |
| 60 | 54 of 60, a point rate of 0.900 |

Forty per stratum is what Task 5 takes.
It demands a point rate of 0.925 from a class asking to be repaired unattended,
which is the right order of strictness,
and it keeps the round affordable:
five strata hold more than forty and are sampled at forty,
five hold between 26 and 39 and are taken whole,
which is 368 units and 1,104 elicitations.

## Governing constraint: this slice measures, and measuring is all it does

The umbrella states one ordering that must not be inverted:
a class is admitted on scored evidence, never on judgment.
That ordering decides what belongs here and what does not.

**This plan changes no predicate.**
Task 2's core change is a refactor with no behavioural difference,
proven by a golden holding every fused fixture's complete suggestion value.
Whether `_fused_suggestion` fires, and what it produces when it does, is exactly what it was.

**This plan draws no repair holdout.**
The ledger binds a predicate,
and v0.9b's widened predicate does not exist yet.
A bundle drawn now would be frozen against the predicate whose successor it is meant to test.
The sequencing is the one v0.4.2 used for its recall repair:
written first, frozen and scored afterwards, by a different session.

**Therefore no class is admissible on what this plan delivers.**
That belongs in the acceptance criteria and not only here.
What this plan delivers is the instrument, a calibration population, a preregistered bar,
and a ledger that can hold a later round to it.

**The ledger hole this plan found is closed, and Task 8 finishes the job.**
The pre-draw freeze named a predicate and an intent and nothing else,
`require_predicate_freeze` accepted any earlier record naming the current predicate,
the sample recorded no freeze identity,
and sealing bound whatever predicate was current to a sample that already existed.
So this was not refused:
freeze A, draw and label a sample, tune to B after reading it, append a freeze for B, seal against B.
That was a defect in accepted machinery rather than a gap in this plan,
so it was repaired on its own and recorded as
[ADR-0022](../../decisions/0022-a-pre-draw-freeze-binds-a-round-and-a-sample.md).
What remains is binding this round's own contract into the same mechanism, which is Task 8.

**This slice's session must not touch v0.9b.**
The standing constraint is that the session tuning a predicate does not label the round that scores it.
Reading 368 repairs is exactly the memory that constraint exists to keep out of a tuning session.

**No path here writes a user's file.**
Hook-side mutation stays where the umbrella left it.

### One objection to answer before a reviewer files it

The draw samples detector **findings**, not labeled true violations,
and ADR-0003 forbids a denominator built from detector output.

This is not that.
ADR-0003's rule protects a recall claim:
candidates drawn from current findings exclude every violation the detector already misses,
which makes the miss unfalsifiable.
The quantity here is conditional on delivery by construction.
"Given that a finding reached the agent, was the repair right"
has the detector's firing in its condition rather than in its denominator,
and a finding the detector never raises has no repair to measure.

The existing corpus measures whether the condition is true.
This one measures what follows from it.
Both are needed, and neither substitutes for the other.

## Group 1 — What is being measured, fixed before anything is measured

### Task 1: Preregister the bar

**Class:** design

**Files:**
- Modify: `tests/corpus/manifest.json`, `tests/corpus/manifest.lock`
- Modify: `tests/corpus_harness.py`
- Modify: `tests/test_corpus_manifest.py`

A floor stated after its labels are read is not a gate.
So the bar goes first, before a single repair has been elicited.

**The bar is an absolute number, and it is not derived from the shipped class.**
The obvious construction — require a candidate to be no worse than the class already trusted —
does not survive contact with the measurement, for three reasons.

The shipped class is 34 boundaries and 32 of them are in one source,
so a bar derived from it is a bar derived from `go-proposal`.

A lower-bound-against-lower-bound comparison is not a non-inferiority test.
It compares two independent one-sample intervals rather than estimating their difference,
and the arithmetic is not close:
a baseline of 10 of 10 has a Wilson lower bound near 0.722,
so a candidate of 36 of 40 clears it at a lower bound of 0.769
while being ten points worse.
Declaring that non-inferior would be exactly the kind of claim this corpus exists to prevent.

And the two sides would not be running the same algorithm.
Today's suggestion replaces the anchor alone (`scripts/check_linefeeds.py:1326-1329`),
while the successor absorbs the line below,
so a comparison between them changes the repair shape and the eligibility class at once
and cannot say which of the two moved the result.

So: **preregister an absolute floor of 0.80 on the candidate's Wilson-95 lower bound.**
At the sample sizes Task 5 draws, that demands a point rate of 0.925 at forty units
and 0.941 at thirty-four.
The number is chosen with the sample size in hand and with no label in existence,
which is the distinction that matters:
knowing what a floor costs is not knowing whether a candidate clears it.

The shipped class is still measured, and it is reported beside every candidate as context.
It is a description of what ships, never the bar.

Preregister, in `manifest.json` under `repair_admission`:

**The denominator.**
A unit is scored when it has a frozen acceptable set and is not ambiguous.
Ambiguous units are excluded from rates and retained as cases,
as the label corpus already treats them.

**The activation rule.**
A candidate class admits repairs only where every other class is absent,
so the units it is scored on are the ones whose **exact set** it activates,
not every unit carrying the class.
A candidate may activate more than one exact set.

**The statistic, and the test, which are per stratum rather than pooled.**
For each exact set a candidate activates,
the rate is the fraction of that stratum's scored units whose machine repair is in the acceptable set,
and its Wilson-95 lower bound must be at least **0.80**.
**Every activated stratum must clear it independently.**

The obvious alternative does not work:
a population-weighted rate across the activated strata, with one Wilson bound over the result.
`wilson` takes one integer success count over one integer denominator
and implements a single-binomial interval (`tests/corpus_harness.py:570-586`),
while a weighted mean across strata has no such denominator;
using it would need a stratified variance estimator this plan does not define.
The unit makes it worse:
`diagnose` emits one finding per match, and Task 5 keeps one record per match,
so several units can share one line and one window and effectively one repair outcome,
which a binomial interval would count as independent trials.
A per-stratum gate needs neither an estimator nor an independence assumption across strata,
and it is strictly the more conservative of the two.

A population-weighted combination is still computed and reported.
It is descriptive, it is labelled as such, and it decides nothing.

**An unreportable activated stratum refuses the candidate.**
It is never dropped from consideration so the remaining strata can carry the claim.
A candidate that reaches prose the round cannot score has not been scored.

**Same algorithm on both sides.**
Whatever repair transformation v0.9b proposes is applied to the shipped class as well,
and both numbers are reported from that one algorithm.
A round that scores two classes through two algorithms is refused.

**Three zero-tolerance conditions, which are conditions and not rates.**
Any one of them refuses a class however well it scores:

- a machine repair that does not preserve the prose,
- a machine repair that changes a carrier, as Task 3 defines carrier validity,
- a machine repair that fires on a unit whose acceptable set holds only the original.
  Automatically repairing a line that should have been left alone is the worst outcome this tool can produce.

**And no class is admissible from calibration.**
Every number above is scored on a holdout round this plan does not draw.

- [x] **Step 1:** Write `repair_admission` into `manifest.json`, every clause above, and repin the lock.
- [x] **Step 2:** `REPAIR_ADMISSION` frozen in `tests/corpus_harness.py`,
      checked against the manifest the way `_reporting_problems` checks `REPORTING`.
- [x] **Step 3:** A digest over the contract, so Task 8 can bind it into a freeze.
      Comparing a manifest against an in-code constant catches one copy moving and not the other;
      it does not catch both moving together after a round is underway,
      and only the freeze binding does.
- [x] **Step 4:** A test that the manifest matches the constant, and that changing either alone is red.
- [x] **Step 5:** A test with a candidate whose point rate clears 0.80 and whose lower bound does not,
      asserting refusal, using the 36-of-40 case above.
- [x] **Step 6:** A test that a class scored through a different algorithm from the shipped class is refused.
- [x] **Step 7:** Record that `FLOOR = 26` is a **preregistered policy minimum**, not a derivation.
      Reportability in `recall` depends on the realized count, the half-width, and the ambiguous fraction
      (`tests/corpus_harness.py:589-638`), none of which are known before labeling,
      so nothing can prove in advance that a smaller stratum is intrinsically unreportable.
      Twenty-six is the size at which a rate of 0.80 first fits inside the frozen half-width,
      and it is taken as a floor on that ground alone.
- [x] **Step 8:** Tests: two activated strata where one is unreportable, asserting the candidate is refused;
      and two activated strata with unequal populations, asserting each is gated on its own bound
      rather than on their combination.

**Acceptance:** the bar is committed before any repair exists,
it does not depend on a 34-unit single-source baseline,
and weakening it after a round begins is caught by the freeze rather than by review.

### Task 2: The repair classes, and the judged line they are read from

**Class:** contract

**Files:**
- Modify: `scripts/check_linefeeds.py`
- Modify: `tests/test_diagnostics.py`, `tests/test_schema.py`
- Modify: `tests/corpus/repairs/measure.py`

Two core changes, and both exist so nothing downstream has to guess what the detector did.

**First: the judged line.**
`diagnose` does not read what `prose_stream` yields.
It applies `without_license_text`, then parses and conditionally strips a trailing suppression carrier,
and only then runs `FUSED_RE` (`scripts/check_linefeeds.py:1345-1389`).
So a harness that re-extracts through `prose_stream` compares different text from the text the finding came from.
`prose_stream` also yields no offsets; those live in `line_offsets`
(`scripts/check_linefeeds.py:771-781`).

Factor that walk into `judged_lines(text, path)`, yielding one record per line the detector judged.
The record has to carry more than the obvious fields, and each addition below has a reason:

| field | why it is there |
|---|---|
| line number, judged prose, judged raw line | what the finding was read from |
| raw span, and the **exact line terminator** | a window is spliced back into the file, and CRLF must survive it |
| **original raw line** | the judged one has had its carrier removed, so the bytes are gone otherwise |
| prose span, leader, tail — **nullable** | `locate_in_line` returns `None` when the prose is absent or not unique (`scripts/check_linefeeds.py:771-798`), and the core refuses to pick an occurrence; the record must not invent one |
| **the exact stripped carrier bytes**, with its parsed offset and kinds | Task 3 requires every tail preserved byte for byte, and a stripped line no longer contains it |
| paragraph identity | the two-line window may not cross a paragraph |
| **the effective suppressed kinds** | a standalone or trailing directive mutates the `suppressions` map during the loop, and the map filters findings after it (`scripts/check_linefeeds.py:1355-1389,1516-1521`); a generator yielding prose alone cannot reproduce that, so the state travels with the record |

`diagnose` consumes it and behaves as before,
which is asserted over the complete diagnostics of every fixture and not only over suggestion values.
Paragraph identity is stable within one call and is not serialized;
a stored record refers to its window by span.
The leader and the tail are read off the raw and prose pair the detector itself used,
which is what makes Task 3's carrier rule decidable.
Nothing downstream re-derives the extractor's own rules for lists, blockquotes, docstrings, or block comments.

**Second: the classes.**
There are three problems with taking `_fused_suggestion`'s refusals as strata unchanged.

*A refusal is not a repair class.*
`_fused_suggestion` asks whether the character before the gap is `!` or `?`
(`scripts/check_linefeeds.py:1312-1318`),
which answers "no" for a period boundary and for a bang behind a closing quote alike.
`FUSED_RE` allows closing quotes, brackets, parens, and emphasis between the punctuation and the gap
(`scripts/check_linefeeds.py:350-355`).
Those are different repairs carrying different risks,
and a rate over their union cannot admit either.
The same holds for the gap test, which merges tabs with repeated spaces,
and for the prefix test, which merges list markers with docstrings and block comments.

*A class must outlive the predicate that refuses it.*
If v0.9b admits periods, the withholding helper stops reporting `terminator_period`,
and the stratum the holdout was drawn on disappears from the taxonomy that named it.
So the class list is its own constant, not a derived view of the current refusals.

*One class is decided outside the function.*
`carrier_stripped` is decided at the call site,
and `judged_lines` is what carries it out rather than a reconstruction in the harness.

The classes, named rather than numbered so a widening cannot renumber them:

| class | when it applies |
|---|---|
| `carriage_return` | a `\r` in the judged raw line |
| `many_boundaries` | `FUSED_RE` matches more than once on the judged prose |
| `protected_span` | a backtick, `<`, or `>` anywhere in the judged prose |
| `prose_not_unique` | the prose does not sit in the judged raw line exactly once |
| `gap_multiple_spaces` | the gap is two or more spaces |
| `gap_tab` | the gap holds a tab |
| `gap_other_whitespace` | any other gap that is not one ASCII space |
| `terminator_period` | the sentence punctuation is `.` |
| `closing_delimiter` | a closing quote, bracket, paren, or emphasis stands between the punctuation and the gap |
| `prefix_list_marker` | the leader is rejected by the suggestion whitelist and begins with a list marker |
| `prefix_other` | the leader is rejected for any other reason |
| `tail_rejected` | anything but whitespace stands behind the prose |
| `carrier_stripped` | a trailing suppression carrier came off the line before it was judged |

Three rules the implementation must keep.

The classes are computed **per match**, not per line.
A line with a period boundary and a bang boundary carries two units with different classes.

The punctuation and the gap are read from the **end** of a match, not the start.
A match may open on a code span carrying punctuation and whitespace of its own,
and the sentence boundary is the one abutting the next sentence's opener.
Reading from the start inflated `closing_delimiter` by an order of magnitude in the first `measure.py`,
which is how this rule was found.

The prefix and tail classes are evaluated **only when the prose sits in the raw line exactly once**.
The shipped function stops at `prose_not_unique` and never reaches them
(`scripts/check_linefeeds.py:1310-1311`),
and testing them against an arbitrary occurrence would invent a class the code never had.

`ws` needs no guard, and the reason belongs in a comment.
`FUSED_RE` requires a non-empty whitespace run after the punctuation,
and the text comes from that match,
so the search cannot fail and its start cannot be zero.

- [x] **Step 1:** `judged_lines(text, path)`, and `diagnose` rewritten over it with no behaviour change,
      proven by a golden over the complete diagnostics of every fixture.
      Cover a standalone `semlf-ignore-next`, a same-line suppression, a carrier-only line,

- [x] **Step 2:** `WITHHOLDING_CLASSES` and `_fused_withholding(record, match)`

### Task 3: The window, the carrier, and what a repair is once normalized

**Class:** design

**Files:**
- Modify: `tests/corpus_harness.py`
- Create: `tests/test_corpus_repairs.py`

This task decides what a repair is as a comparable object.

**The window is one or two lines.**
A suggestion today replaces the anchor alone,
and the measurement says that is the wrong window for most of the population:
2,771 of the 3,851 units in the stratum a period widening activates carry a `wrap` too,
and v0.9a shipped the rule that the rejoin comes before the split.
So the window is the anchor and the line beneath it —
the same window v0.9b's successor to `_fused_suggestion` will replace.

A `fused` finding on the **last judged line of a paragraph** has no line beneath it.
`diagnose` requires no successor (`scripts/check_linefeeds.py:1391-1432`),
while the boundary instrument only builds units from adjacent pairs
(`tests/corpus_harness.py:263-274`).
Reusing that shape unchanged would silently drop those findings.
The window therefore has an explicit one-line form,
and the lower line must belong to the **same paragraph**,
which `judged_lines` reports.

**Normalization runs through `judged_lines`, not through a prefix regex.**
`_SUGGESTION_PREFIX_RE` validates an already-separated prefix; it does not find one
(`scripts/check_linefeeds.py:1281-1292`).
It also rejects list markers deliberately,
while the Markdown extractor strips a list marker from prose and keeps it in raw
(`scripts/check_linefeeds.py:919-925`),
which is exactly the `prefix_list_marker` stratum.
Normalizing with that regex could not score a stratum it exists to score.

So the replacement is spliced into the file's lines,
the file is re-read through `judged_lines`,
and the repair is compared against the original in the detector's own terms.

**A repair normalizes to four facts.**

```python
def normalize_repair(unit, replacement, text, path):
    """Reduce a rewrite to what makes two rewrites comparable.

    The replacement is spliced into the file and re-read through `judged_lines`,
    so a list marker, an indent, a docstring, and a comment leader are all handled
    by the detector rather than by a second opinion about what a carrier looks like.

    `preserving`     the prose is the same text, differing only in where it breaks.
    `breaks`         where it now breaks, as offsets into the window's joined prose.
    `carrier_valid`  every produced line carries the leader the rule below allows.
    `intact`         re-reading yields judged prose lines in the same paragraph,
                     and no line turned into a fence, a heading, or excluded markup.
    """
```

`preserving` compares the joined prose with internal whitespace runs collapsed to one space.
`breaks` is meaningful only when `preserving` and `intact` both hold.
The original window is a point in this space:
a two-line window's original is one break at the length of the anchor's prose,
and a one-line window's original is no breaks at all.
So **"leave it alone" is an answer the corpus can represent**,
which matters because a finding whose right answer is to change nothing is an outcome here rather than a hole.

**The carrier rule, decidable from what `judged_lines` reports.**
Each judged line reports its leader and its tail.
A repair is carrier-valid when:

- a line produced by splitting the anchor carries the anchor's leader, byte for byte;
- a line that was not split carries its own leader, byte for byte;
- a rejoin drops the leader of the line it absorbed and keeps no trace of it;
- every tail is preserved on the line it belonged to, and no tail moves across a break;
- and the file's newline style is unchanged.

Nothing else is carrier-valid.
A repair that preserves the prose and breaks this rule is a defect,
it is recorded on the unit,
and Task 1 makes it a zero-tolerance condition for admission.

**Composing a repair algorithm's output.**
`_fused_suggestion` returns two lines replacing the anchor.
To score it in this space, those lines are spliced in place of the anchor
and the untouched lower line is kept.
A test asserts the lower line is byte-identical after composition,
because a composition that dropped it would score the shipped class as catastrophic.

- [x] **Step 1:** `repair_window(record, text, path)`, one-line and two-line forms,
      refusing a lower line from another paragraph.
- [x] **Step 2:** `normalize_repair` as above, over `judged_lines`.
- [x] **Step 3:** `carrier_valid(unit, replacement)` implementing the five clauses.
- [x] **Step 4:** `compose(unit, lines)` for scoring any anchor-only algorithm, and its byte-identity test.
- [x] **Step 5:** Tests covering, at minimum:
      a last-line finding; a repair touching only the lower line; a three-line repair;
      a bulleted item and a multi-digit ordered item with indented continuations;
      a nested blockquote; a docstring; a decorated and an undecorated block comment;
      an anchor and a lower line with different leaders;
      a split that must repeat the anchor's leader;
      a rejoin that must drop one;
      a line carrying a suppression carrier, in both the shared-suffix and rejected forms;
      an unchanged window; a reworded window; a window with a clause dropped;
      a prose-preserving repair that corrupts a carrier;
      and a replacement that turns a line into a fence, a heading, or a table row.

**Acceptance:** every shape in the measured population is representable,

and doing nothing is an answer.

### Task 4: The acceptable set, drawn from a bounded universe

**Class:** design

**Files:**
- Modify: `tests/corpus_harness.py`
- Modify: `tests/test_corpus_repairs.py`
- Create: `tests/corpus/repairs/REPAIRING.md`

A label has three values and a repair does not.

**A repair has more than one correct answer.**
A long fused line can be split at either of two real clause boundaries,
and both results are correct prose.
So the settled outcome is a **set of acceptable break vectors**,
and the question a later score asks is whether the machine's answer is in that set.

**Completeness cannot come from open-ended enumeration.**
Asking three passes what else they would accept improves on asking none,
but all three can omit the same valid break and produce apparent agreement,
which recreates the failure it was meant to fix.
So the candidates are **generated, not invented**,
and the generator is mechanical rather than a judgment about where a clause opens.

There is no single list in this repository to generate from, which is why the rule has to be chosen here.
`CONNECTORS` is broad and exists to *withhold* a `wrap` (`scripts/check_linefeeds.py:276-315`).
`BOUNDARY_HINT_RE` is deliberately **not** derived from it,
because it *raises* an advisory and so keeps only strong punctuation and six comma-led words
(`scripts/check_linefeeds.py:407-428`).
`SKILL.md` names subordinators and then says its examples do not exhaust the class.
`FUSED_RE` matches one restricted sentence shape, not every sentence break the rule permits.

**The generator therefore takes a lexical superset and lets the passes reject it.**
A position is a candidate cut when it sits, in the window's joined prose, immediately after any of:

- a `FUSED_RE` sentence boundary,
- a `;`, a `:`, or an em dash,
- a comma.

No semantic test is applied.
Offering a comma that turns out to join a compound object is correct behaviour:
the passes reject it, and the rejection is data.
Asking the generator to decide would put the clause judgment back in the instrument,
which is the thing this project leaves to a reader.

**The bound is explicit.**
At most **two** distinct cut positions are combined,
which is what a two-line window can produce as three lines.
With `n` positions the universe is `1 + n + n(n-1)/2` candidates, counting the original.
**A window offering more than six positions leaves the sample as a defect**,
the way the label corpus drops a unit whose sampling was wrong,
because 6 positions is 22 candidates and a pass judging more than that is guessing.
The defect is recorded with its position count rather than silently dropped.

**Each pass accepts or rejects every generated candidate**, and separately marks the one it would make.
`accept` and `reject` together must partition **every** generated candidate including the chosen one,
and the chosen one must appear in `accept`.

**A candidate a pass had to invent invalidates the round for that unit.**
If a pass reports a repair the generator did not offer,
the generator was wrong about the universe,
and an acceptable set assembled from an incomplete universe is not complete.
That unit is refused and its generator input is recorded as an instrument defect.
It is not patched by a maintainer adding the missing candidate afterwards,
because three-pass coverage of a universe is the only thing making the set complete,
and a candidate added after the coverage failed has no coverage.

**Every candidate is validated independently.**
`preserving`, `carrier_valid`, and `intact` are computed per candidate, not per pass.
A candidate that fails any of them never enters an acceptable set,
however many passes accepted it.

The rule:

```python
def repair_resolution(passes, candidates):
    """Settle three per-candidate verdicts into an acceptable set, or refer them.

    A candidate is acceptable when it is valid and every pass accepted it.
    A candidate every pass rejected is rejected.
    A candidate the passes split on is referred, and so is the whole unit:
    a disagreement about where a line may be cut is the defect source ADR-0008 names,
    and it is the same question a widening asks.
    """
```

- every candidate unanimous, and at least one accepted: `settled`.
- otherwise `adjudicated`, and a maintainer states the acceptable set,
  which may hold a candidate no pass proposed, and may hold only the original.
- a maintainer may record `ambiguous`,
  meaning the rule does not settle what this line should become.
  Ambiguous units leave the denominator and stay as cases.

**Nothing may enlarge an acceptable set after a machine repair has been read.**
Promotion is the only place a repair algorithm is read, and it runs last.
A test enforces the ordering rather than a comment asking for it.

`REPAIRING.md` is the procedure a pass is given,
and it stands to this corpus as `LABELING.md` stands to the other one.
It says what a repairer sees, what it must return, and what never to do.
It does **not** say how three passes are combined,
for the reason `LABELING.md` gives for the same omission:
a pass that knows which answer survives a disagreement answers a different question.

- [x] **Step 1:** `repair_candidates(window)` generating the bounded universe from the rule.
- [x] **Step 2:** A test that the generator is a function of the rule and the prose alone,
      with a monkeypatched suggestion secret asserted absent from every generated candidate.
- [x] **Step 3:** `repair_resolution` and its tests, one per branch.
- [x] **Step 4:** Per-candidate validation, with tests for
      a non-preserving candidate, a carrier-invalid candidate, and a candidate that stops being prose,
      each excluded from the acceptable set even when unanimously accepted.
- [x] **Step 5:** Tests that two passes accepting `{A, B}` against one accepting `{A}` refers,
      and that a unit where every pass omitted a generated valid candidate
      still puts that candidate to them rather than settling around it.
- [x] **Step 6:** A test that promotion cannot add a candidate after reading a machine repair.
- [x] **Step 7:** `REPAIRING.md`, pointing at `SKILL.md` as the normative rule the way `LABELING.md` does.

**Acceptance:** the acceptable set is a verdict on a generated universe rather than a union of guesses,
every member of it is independently valid,
and no set grows after the machine has spoken.

### Task 5: The draw

**Class:** design

**Files:**
- Create: `tests/corpus/repairs/draw.py`
- Modify: `tests/corpus_harness.py`
- Modify: `tests/test_corpus_sampling.py`, `tests/test_corpus_quotas.py`

The population is every `fused` boundary the detector raises on the calibration sources,
enumerated through each source's own `selection_command`.
Not every prose boundary, as in the label corpus:
a repair exists only where a finding was delivered, which is the conditional this corpus measures.

**The strata are exact class sets, because they partition the population.**
`level_of` returns one scalar level per dimension (`tests/corpus_harness.py:476-510`),
and a unit refused by three classes belongs to three of them,
so a top-up on one class raises another class's members' chance of selection.
A raw marginal fraction over such a draw is biased for the population marginal.
Exact sets are disjoint, so a stratified draw over them has known inclusion probabilities
and a population-weighted estimator that is not.

Per stratum the sample records the population size, the drawn size, and the inclusion probability.
A class marginal is then a weighted derived report, and is labelled as one.

```python
BASE = 0            # every unit comes from a stratum quota; nothing is drawn at random
SEED = "repairs-1"
PER_SET = 40        # or the whole stratum where it holds fewer
FLOOR = 26          # the smallest stratum the frozen rules let print a rate
```

There is no random base.
The label corpus uses one because its dimensions overlap and a base spreads what nothing quotas;
here the strata are disjoint and enumerable, so a base would only add unweighted units.

A stratum below `FLOOR` is drawn at zero and **declared** in the sample as unreportable.
It is not silently absent, and Task 11 makes it inadmissible rather than merely unmeasured.

- [x] **Step 2:** `draw_strata(population, quotas, seed)` over disjoint exact sets,
      recording population size, draw size, and inclusion probability per stratum.
- [x] **Step 3:** `weighted_rate(units, strata, activated)` computing a candidate rate

- [x] **Step 4:** Shortfall reporting over the declared universe from `WITHHOLDING_CLASSES`,
      so an empty class and an unreportable stratum both appear as lines rather than as absences.
- [x] **Step 5:** `draw.py` writing `sample.json` with the strata table, the seed, and every shortfall.
- [x] **Step 6:** A test on a synthetic overlapping population

### Task 6: The elicitation batch

**Class:** design

**Files:**
- Create: `tests/corpus/repairs/batch.py`
- Modify: `tests/corpus_harness.py`
- Modify: `tests/test_corpus_repairs.py`

A pass must see what a repairing agent sees, minus the answer.
Being precise about the "minus" is the point of this task.

**What a pass is shown is a blinded hook body, and the plan says so rather than claiming otherwise.**
`format_findings` renders the report body and never reads a suggestion
(`scripts/check_linefeeds.py:1548-1557,1570-1630`).
But `deliver` is what a host actually sends,
and it appends a suggested-replacement block for any finding carrying one,
followed by the judgment and suppression notes
(`scripts/check_linefeeds.py:1943-1975`).
So the batch is `format_findings` output and not `deliver` output,
and that is a deliberate redaction rather than a reproduction.
It follows that the elicited defect rates describe agents given a blinded body,
not agents given complete hook feedback.
Task 12 records that limit where a reader of the results will find it.

**The stimulus is stored, not recomputed.**
Re-rendering at batch time would need the extractor's state for the whole file —
block comments, docstrings, fences, and everything above the window —
which a one-or-two-line window cannot reproduce.
So the drawn unit carries the exact rendered body,
and `batch.py` lays out stored text rather than calling the detector.

**The rendering is pinned exactly**, because each of these changes the text:

- every finding on the anchor line is included, `fused` and any co-anchored `wrap` or `long`,
  since ADR-0021 is the reason a `wrap` travels with the block at all
  and the repair it invites is the rejoin this corpus measures;
- `snippet=False`, so the report says "line N" rather than "line N of your edit";
- `skill_hint=True`, matching what a host sends when the skill is installed;
- the long-line limit in force, recorded on the unit,
  since `format_findings` prints it (`scripts/check_linefeeds.py:1583-1607`).

The sample also pins the digests of `SKILL.md`, `REPAIRING.md`, and the rendering code,
so a changed rule refuses rather than silently changing the stimulus mid-round.

**What it must never show:** a suggestion, another pass's answer, or a class name.

The answer shape:

```json
[{"id": "<unit id>", "choose": "<candidate id>",
  "accept": ["<candidate id>", "..."], "reject": ["<candidate id>", "..."],
  "missing": [["<line>", "<line>"]]}]
```

`choose` is the repair the pass would make, from the generated candidates.
`accept` and `reject` are its verdict on every other candidate, and together must cover them all.
`missing` is any repair it would make that the generator did not offer,
which is a defect report about the generator.
Choosing the candidate that is the unchanged window is how a pass says to change nothing;
it is one candidate among the others, with no flag of its own to attract the undecided.

Order is derived from the pass's name, as `labeling_batches` already does.

      the stored body, and the generated candidates.
- [x] **Step 3:** A test that every batch reproduces byte-for-byte with the source checkout deleted.
- [x] **Step 4:** A test that a changed `SKILL.md`, `REPAIRING.md`, or long-line limit
      refuses on a digest mismatch rather than changing the stimulus.
- [x] **Step 5:** A test over a fused line carrying `wrap` and `long` as well,

- [x] **Step 6:** Leakage tests: a monkeypatched suggestion secret,
