# v0.6 umbrella — repository tooling and lifecycle

**Status:** approved design, 2026-08-13.
Slice plans are written one at a time against this frame;
this file does not repeat what a slice plan will specify.

## Purpose and acceptance signals

v0.6 turns the kit from agent-only into repository tooling.
Three signals define done:

- go-secs' committed snippet says `semlf --file` with no absolute path in it.
- pre-commit runs `--staged` through the packaged CLI.
- An install has a full lifecycle:
  status, uninstall, doctor, and a managed upgrade that refuses hand-edited copies.

## Architectural frame

Settled by ADR-0004 and ADR-0011, restated here as constraints on every slice:

- The portable core stays one stdlib-only Python 3.9+ file, and hooks keep invoking it bare.
  The zipapp path is for the CLI;
  hook latency was measured against the bare core and stays there.
- The `semlf` CLI is a separate module owning git snapshot selection, subcommand routing,
  installation lifecycle, doctor, and rendering.
- Config discovery lives in the core with an explicit start directory and precedence order,
  and the CLI reuses that one function,
  so hook and CLI always read the same configuration.
- The CLI contract — flags, config schema, diagnostic schema, exit codes —
  must not leak Python details,
  keeping ADR-0011's Go option cheap to exercise.

## The three slices

Each slice runs the full established process:
plan → external review to zero P0/P1 → subagent-driven execution → two-track final review → scoped squash → ff-merge.

### v0.6a — the CLI exists

- `semlf.pyz` promoted from the ADR-0004 proof to a built, releasable artifact.
- Subcommand skeleton with the file-checking path.
- Config discovery in the core plus a project configuration file.
  One design point is left to the slice plan:
  the file format must parse with the 3.9 stdlib,
  which rules out `tomllib` (3.11+) and leaves JSON or INI unless a mini-parser earns its keep.
- `SEMLF_*` environment rename with a deprecated alias
  (`adapters/opencode/semantic-linefeeds.ts:44`).
- `install.py` fixes:
  `--agentsmd` refuses to default to the current directory,
  and `status()` reports against the resolved install target.
- Installer-managed CLI install:
  the pyz plus a shim at `~/.local/bin/semlf`,
  and the AGENTS.md snippet rewritten to say `semlf --file`.

### v0.6b — git modes

- A provider contract for content sources, so every mode shares one seam.
- `--staged` first, reading index blobs, with an index-versus-worktree test matrix.
- `--diff` and `--changed` on the same contract.
- `.pre-commit-hooks.yaml`, only after the staged mode has its tests.
- Windows paths and CRLF become testable here, across every adapter.

### v0.6c — lifecycle and distribution

- `uninstall`, covering skill removal (ADR-0006's deferral lands here).
- `doctor`, replaying a synthetic payload end to end rather than checking that files exist,
  and collecting the platform evidence ADR-0011's gate needs.
- Agent auto-detection for `install`.
- A provenance manifest recording installed digest and version,
  so an untouched older release upgrades while a hand edit refuses.
- `pipx` and `uv tool` distribution,
  with the zipapp retained for air-gapped and mirrored installs.

## Out of scope, already decided

- `.tmpl` support is deferred with its entry condition recorded in the roadmap.
- The Go port waits behind ADR-0011's field-evidence gate.
- New languages, an LSP, and an aggressive auto-formatter stay non-goals.

## Validation

Repo conventions hold for every slice:
inline-marker fixtures, extractor goldens, payload replays,
the full suite before any commit,
and the Markdown self-check on every touched file.
The index-versus-worktree matrix is v0.6b's core test investment.
`sh docs/proofs/zipapp-packaging/verify.sh` guards the packaging property throughout.
