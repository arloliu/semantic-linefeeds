# v0.4.1 Trust and Precision Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop the detector from blocking edits it was never meant to block,
then stop it from accusing prose that is already correct.
Both defects are live today, and both cost trust faster than any missing feature.

**Architecture:** Every change lands in the single stdlib core `scripts/check_linefeeds.py`,
except the opencode adapter's rendering path and the corpus tooling under `tests/`.
The hook entry points gain a delivery layer that separates *status* from *transport*,
because a non-blocking result has to travel a different channel than a blocking one:
exit-0 stderr reaches no model in either host.
The two hosts accept the same non-blocking shape,
so the layer exists to split blocking from advisory, not to translate between hosts.
No new module, no new dependency, no package split.

**Tech Stack:** Python 3.9+ stdlib only;
pytest for the core; `bun test` for the opencode adapter.

**Decisions this plan implements:**
[ADR-0001](../../decisions/0001-long-never-blocks-an-edit.md),
[ADR-0002](../../decisions/0002-wrap-withdrawn-from-default-feedback.md),
[ADR-0003](../../decisions/0003-precision-measured-against-labels.md).

## Task classes, and the tier each gets

Tasks below are tagged with a class rather than a model name,
so that a model rename touches this table and nothing else.

| Class | Covers | Tier |
|---|---|---|
| **mechanical** | Edits whose correct form is already decided: constants, docstrings, help text, doc sync | Cheapest capable model, low effort |
| **contract** | Work that must match an external shape exactly: host JSON, adapter behavior, exit codes | Mid-tier model, medium effort |
| **design** | Work where the right answer is not yet known: corpus sampling, label schema, holdout enforcement | Strongest model, high or extra-high effort |
| **adversarial** | Work that must prove a test *fails*: mutation testing, false-positive hunting | Mid-tier model, high effort, several independent runs |

Current concrete assignment, as a snapshot to be updated in this one table:
mechanical → Haiku-class at low;
contract → Sonnet-class at medium;
design → Opus-class at high;
adversarial → Sonnet-class at high, three independent runs whose disagreements are investigated rather than averaged.

Two rules that matter more than the tiers:

- An **adversarial** task is graded on whether the mutation makes a named test go red.
  A run that reports "the code looks right" has not done the task.
- A **design** task may not be split across models mid-way.
  The corpus schema and its enforcement tooling are one decision.

## Global Constraints

- The core stays one file, Python 3.9+, stdlib imports only.
- `--file` keeps its kinds and its exit codes in this release, in any task.
  It remains the audit surface, and it keeps reporting `wrap`.
  One exception, taken knowingly:
  the renderer is shared, so an advisory-only report closes with different wording in both modes.
  A renderer that told a human to fix what it tells an agent to leave alone was the alternative.
- Group 1 lands before group 2.
  Group 1 is the trust repair and needs no new design;
  group 2 depends on a corpus that does not exist yet.
- Group 2's abbreviation exclusions and `wrap` withdrawal land in **one commit**.
  `fused` is not safe as the sole blocking kind before the exclusions,
  so shipping the withdrawal first would leave a blocking kind that misfires on `vs.` and `cf.`.
- Every task ends green: `python3 -m pytest tests/ -q`, plus `bun test adapters/opencode/` when the adapter changed.

### Task 1: Separate status from transport in hook delivery

**Class:** contract

**Files:**
- Modify: `scripts/check_linefeeds.py`
- Create: `tests/test_hook_delivery.py`

**Interfaces:**
- Produces: `blocking_kinds(findings) -> bool`,
  `deliver(reports, snippet=True, note=None) -> int`.
  `deliver` writes the report and returns the exit status;
  every hook entry point calls it instead of printing directly.
- Consumes: existing `check()` and `format_findings()`.

The signature took two deviations from the one first written here,
each forced by a case the original could not express:

- `reports` is a sequence of `(path, findings)` pairs, not a single pair.
  One Codex patch can touch several files,
  and the non-blocking transport is a single JSON object,
  so a per-file call would emit concatenated objects that parse as nothing.
- There is no `agent` parameter.
  Both hosts read non-blocking feedback from the same
  `hookSpecificOutput.additionalContext` shape,
  so the transport does not vary by agent and an agent argument would go unread.

- [x] **Step 1: Write the failing tests**

`tests/test_hook_delivery.py` asserts the matrix from ADR-0002, per agent:

| Result | Status | Stream | Shape |
|---|---|---|---|
| `fused` | 2 | stderr | current text report |
| `long` only | 0 | stdout | host JSON with the advice in `additionalContext` |
| `fused` + `long` | 2 | stderr | one combined report, advice not duplicated |

Assert the **parsed JSON**, not a substring.
A test that greps stderr cannot distinguish "delivered" from "written where the model never reads it",
which is the exact defect this task exists to fix.

- [x] **Step 2: Implement `deliver`**

Status comes from the kinds present;
transport comes from the status.
Exit 2 keeps stderr.
Exit 0 emits one JSON object on stdout with `hookEventName: "PostToolUse"`.

- [x] **Step 3: Route both hook entry points through it**

`run_hook_claude` and `run_hook_codex` stop returning a bare status and stop printing.
The Codex path keeps its approximate-position note.

**Acceptance:** every row of the matrix, for both agents, asserted on parsed output.

**The kind-aware closing line belongs to this change.**

One consequence to accept knowingly:

### Task 6: The labeled positive corpus, manifest, and holdout

**Class:** design

This is the only task in the release whose answer is not already known,
and it should not be started in the same session as the tasks around it.

**Files:**
- Create: `tests/corpus/labeled/`, `tests/corpus/manifest.json`,
  `tests/corpus/freeze.jsonl`, `tests/corpus/LABELING.md`,
  `tests/corpus/labeled/NOTICE.md`
- Modify: `tests/test_corpus.py`

**The requirements it must satisfy**, from ADR-0003:

- Candidates are generated **independently of detector output**.
  Sampling from current findings would exclude every violation the detector already misses,
  which makes recall unfalsifiable.
- Every candidate is labeled true, false, or ambiguous.
  Ambiguous cases are excluded from rates and kept as qualitative cases.
- Recall is detected true violations over the **frozen** denominator, per kind and stratum.
- Strata for `wrap`: prose width, raw end column, indentation depth, language,
  Markdown nesting, trailing inline markup, list-item adjacency,
  paragraph line count, eligible-anchor count.
- Calibration and holdout come from separate sources.
- The manifest records source, commit, selection command, labels, strata, and accepted misses,
  and a test rejects an unexplained change to any of them.

**The four answers.**
These are binding.
The manifest schema and the harness implement what is written below,
and changing any of them means changing this section first.

#### The sampling frame

A candidate is neither a file nor a paragraph.
`wrap` is a property of an adjacent line boundary inside one paragraph, attributed to the upper line
(`scripts/check_linefeeds.py:556-568`),
and `fused` is a property of a single line (`scripts/check_linefeeds.py:549`).
Both kinds are labeled on the same sampled units.
ADR-0002 requires knowing, for every labeled true `wrap`,
whether a valid `fused` also covers it,
and one reading yields both labels.

Candidates are enumerated by the checker's own `prose_stream()`.
That aligns the unit with the text the detector actually sees,
at a stated cost:
every reported rate means recall over the prose the extractor yields,
never recall over prose at large.
The extractor skips four-space-indented lines
and strips at most one blockquote marker and one list marker
(`scripts/check_linefeeds.py:263-265`, `scripts/check_linefeeds.py:288-290`),
so deeply nested prose never enters the stream.

That blind spot gets a measurement rather than a disclaimer.
A second, smaller sample is enumerated by a naive rule —
every comment block and every Markdown paragraph —
restricted to units the extractor never yields.
It is labeled the same way and reported on its own,
and it is never merged into the main rates,
because extraction scope and judgment error are different failures.

Sources are six disjoint public projects, three per side, symmetric in composition:
one self-authored project, one third-party project for code comments,
and one third-party project whose prose is mostly Markdown.
Calibration takes `arloliu/styx`, whose comments wrap near column 80.
The holdout takes `arloliu/helix`, whose comments wrap near column 72.
Both sides therefore carry a wide and a narrow wrapping column,
so the prose-width and end-column strata do not collapse on either side.

Mixing self-authored and third-party sources on **both** sides is deliberate.
A predicate calibrated only against one author's habits fails the holdout for a reason nobody can interpret,
and under ADR-0003 that failure costs the holdout permanently.
The holdout must test generalization to unseen projects,
not generalization to a second author.

Third-party sources qualify on evidence that never touches detector output:
the project is public,
its license is permissive,
its comment line-length distribution shows a mode at a fixed column,
and this tool has never run over it.
Choosing sources by finding density would repeat, at repository granularity,
the exact error ADR-0003 forbids at candidate granularity.

Nine strata cannot be crossed.
Even two levels each is 512 cells, which no hand-labeled corpus fills.
So quota sampling applies only to the structurally rare dimensions —
Markdown nesting, trailing inline markup, list-item adjacency, deep indentation —
while the rest are sampled at random and arrive spread on their own.
All nine are recorded for every unit.
Reporting is per-dimension marginals,
and the manifest carries the full covariate vector per unit
so any cross a reader wants can be recomputed without trusting the split chosen here.

Eligible-anchor count is recorded and reported but never drives a quota.
Its definition tracks half of the detector's own condition,
so selecting on it is a diluted form of sampling from findings.
The manifest states its definition in purely geometric terms,
and the corpus tooling computes it rather than importing it from the checker.

Sample size is a rule, not a number,
because the prevalence of true violations among sampled boundaries has never been measured.
Each reported level needs at least `M` true violations;
the pilot measures prevalence `p`;
the sample per level is `ceil(M / p)`.

#### Labels and disagreement

Labels come from three passes by **different model families** —
Claude, the Codex CLI, and the agy CLI —
each blind to detector output and to the others.
Two passes from one family share a prior,
so they agree confidently on the same wrong cases,
and their agreement rate would read as quality while measuring only correlation.

Resolution is deliberately asymmetric,
because the gate that decides this release is zero false positives
and a label of "not a violation" is the only material that can refute a predicate:

| Outcome | Resolution |
|---|---|
| All three agree | The label stands |
| Any labeler says "not a violation" against the others | The maintainer adjudicates, with the reason recorded in the manifest |
| Split between "violation" and "ambiguous" | Ambiguous |
| Three-way split | Ambiguous |

The last two rows overlap, and the overlap resolves in favor of the later one.
A three-way split is ambiguous,
and the refutation row applies only where a "not a violation" stands against labelers who agree with each other.

Reading it the other way was tried first and measured.
Across 360 judgments in two pilot rounds, every ambiguous answer arrived beside a refutation, nine out of nine,
so all of them became adjudications and no unit ever carried the ambiguous label.
A rule that withholds a rate from a level thick with ambiguity cannot fire against a label nothing produces.

The cost is real and accepted:
a refutation buried inside a three-way split no longer reaches the maintainer.
That is the narrower loss.
The alternative left the corpus with an instrument that had never once moved.

Ambiguous is excluded from rates by ADR-0003,
which makes it a quiet drain on the denominator:
the hardest boundaries are exactly the ones the detector gets wrong.
So the ambiguous fraction is a reported number per level,
and a level whose ambiguous fraction exceeds 25% reports no rate at all.

The normative source for what counts as a violation is
`skills/semantic-linefeeds/SKILL.md`, pinned by digest in the manifest.
The corpus must measure the standard the tool publishes,
and a separate rulebook would let the two drift without anyone noticing.
A test fails when that digest changes,
forcing a decision about relabeling rather than allowing silent divergence.
`LABELING.md` adds procedure only:
when to answer ambiguous, how non-English prose is handled,
and which lines never become candidates —
the never-break classes that file already names.

Labelers see candidates in an order randomized per labeler, in bounded batches,
with no detector output present.

#### Holdout enforcement

The adversary is not an attacker.
It is an agent with the whole repository in its context,
tuning a predicate, reading whatever is readable.
Plaintext in the working tree is contamination by default,
which is why a rule that says "do not look" never fires.

The holdout therefore lives in the repository as ciphertext,
under an HMAC-SHA256 counter-mode keystream from `hmac` and `hashlib`, stdlib only.
Stated plainly:
this is not protection against cryptanalysis,
and it is entirely effective against the threat that exists.
Committing the ciphertext also commits the content,
so no later holdout can be substituted for one that proved inconvenient.

The passphrase is never stored on the machine.
An agent can read `~/.config` as easily as the repository.
The maintainer types it at the single evaluation,
which makes "a human is present for a one-shot event" a mechanism rather than a resolution.

Before decrypting, the harness requires a freeze record in `tests/corpus/freeze.jsonl`,
append-only and committed, holding the predicate source digest,
the calibration manifest digest, the rate-reporting rules,
and the digest of the ciphertext it intends to open.
The result is appended afterward, referring to that freeze record.

One bundle, one evaluation.
The harness refuses any holdout whose ciphertext digest already appears in a completed evaluation record.
This is what turns ADR-0003's rule —
a tuned retry needs a new, untouched holdout —
into something a tuner cannot route around:
tuning changes the predicate digest,
the freeze record stops matching,
and scoring is refused until a new bundle with a new digest is committed in the open.

Two consequences follow, and both are accepted:

- The holdout is labeled **last** and sealed immediately,
  by a run that writes no plaintext into the working tree.
  The rubric must therefore be stable before holdout labeling begins.
- Losing the passphrase destroys the holdout.

One residual gap is recorded rather than claimed away.
The session that labels the holdout has seen its contents,
so it must not be the session that later tunes a predicate.
Nothing enforces that;
it is a protocol note in the manifest, and it is honest to call it one.

#### The minimum below which no rate is reported

The build gate and the reported rate are separate instruments.

The gate is per-unit and needs no arithmetic.
Every labeled true violation carries a frozen detected-or-accepted-miss status,
asserted on exact `(line, kind)` identity,
so a single unit that slips from detected to missed turns the suite red.
It works at a sample of one,
which means small strata are guarded rather than excused.

A rate is printed only when both hold:
at least 10 labeled true violations in the level,
and a Wilson 95% interval whose half-width is at most 15 points.
The interval rule does the work a bare count cannot:
near-certain rates are pinned down by few samples,
while a rate near one half needs many.
The manifest records the interval method,
so a rate cannot be made reportable by switching estimators.
Below the bar the report prints `x/n` and no percentage,
and the level joins no comparison.

A level whose ambiguous fraction exceeds 25% reports no rate whatever its size.

#### Licensing of vendored prose

Unit text is stored in the repository,
because the tests run offline and a reviewer recomputes rates from the manifest.
Third-party sources are therefore limited to Apache-2.0, MIT, and BSD.
Each unit records repository URL, commit, path, line range, and SPDX identifier,
which satisfies attribution and sampling auditability with one record.
`tests/corpus/labeled/NOTICE.md` lists every source project, its license, and its copyright line.
Excerpts stay minimal:
the paragraph around the candidate and the context needed to judge it, never whole files.

- [x] **Step 4:** Wire the recall floors.

Every rate the corpus can support is recorded as a floor, per kind and per stratum,

A rate nobody records is not a gate:
it drifts down one detection at a time and no run ever fails.
The reporting rules decide what may carry a floor at all,
and a floor stated for a level those rules withhold is itself a failure —
otherwise a corpus satisfies every floor by shrinking until nothing can contradict one.
The strata a rate may be broken down by live in code rather than in the manifest,
because a stratum the manifest can drop is a floor the manifest can drop.

The holdout floors are stated now, before the holdout is labeled, at 0.68 for both kinds.

- `markdown_nesting` of 2 holds four boundaries in a population of 41,307 and can never carry a rate.

### Task 7: Withdraw `wrap`, exclude abbreviations, repair emphasis, list items, and blockquotes

**Class:** contract

**Files:**
- Modify: `scripts/check_linefeeds.py`
- Modify: `tests/test_detector.py`, `tests/fixtures/`

**One commit.**
The withdrawal and the abbreviation exclusions ship together
because `fused` is not safe as the sole blocking kind before them.
Each of these is a single sentence, and each is reported as `fused` today:

```text
Compare TCP vs. UDP behavior.
For background, cf. Figure 2.
```

- [x] **Step 1:** Abbreviation exclusions, derived from the **active** regex rather than guessed.
      `Fig.`, `No.`, and `Eq.` cannot match the current case-sensitive pattern at all,
      so a list containing them was not derived from the rule it claims to amend.
      The derived list is `cf`, `esp`, `viz`, `vs`.
      `etc.` and `resp.` were considered and left out:
      both match the rule, and both commonly do end a sentence,
      so excluding them would trade a false positive for a miss on the same material.
- [x] **Step 2:** Peel balanced closing emphasis delimiters for the terminal-punctuation test only.
      Never expose punctuation inside a code span:
      the backtick is already a legitimate ender, so stripping code markers would create a new false positive.
- [x] **Step 3:** Emit a paragraph break at every Markdown list item.
      Continuation lines within one item stay in the same paragraph.
- [x] **Step 4:** Strip blockquote markers before the structural tests, not after them.
      `prose_lines_markdown` removes the marker on its last line,
      by which point every rule that decides a line is not prose has already run against the marker.
      Inside a blockquote the extractor therefore loses all six exemptions at once:

      | Line | Outside a blockquote | Inside one |
      | --- | --- | --- |
      | ```` ```go ```` | opens a fence | prose, and the fence never opens |
      | four-space indent | code | prose |
      | `## Heading` | skipped | prose |
      | `\| a \| b \|` | skipped | prose |
      | `[ref]: dest` | skipped | prose |
      | `<div>` | skipped | prose |

      Strip a leading run of markers, each `>` followed by at most one space, before anything else,
      and keep the remaining indentation intact so the four-space rule still sees it.
