# v0.4.2 What the Holdout Found Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair the five defects the holdout round exposed,
and rebuild the instrument that exposed them.

Four are false positive classes the detector was never known to have.
The fifth is a recall hole two independent samples agree on.
None of them was found by reading the code.

**Architecture:** Four of the five land in `prose_lines_markdown` and `prose_lines_code`,
which is where a line stops being prose.
The fifth changes the line-ender test itself, and that is the one with a dependency.
No new module, no new dependency, no package split.

**Tech Stack:** Python 3.9+ stdlib only;
pytest for the core; `bun test` for the opencode adapter.

**Decisions this plan implements:**
[ADR-0003](../../decisions/0003-precision-measured-against-labels.md).

## Where the evidence came from

Every item below has a labeled unit behind it, and none was invented from a description.

| Defect | Evidence | Strength |
|---|---|---|
| Commented-out code in a doc comment | the holdout's only false positive, plus adjudication | 1 of 331 |
| A Markdown table row that does not start with a pipe | adjudication | 1 boundary, 2 records |
| A second licence block in one file | adjudication | 1 boundary, 2 records |
| A rule of dashes used as a divider | adjudication | 1 boundary, 1 record |
| A line ending in inline markup | both samples, independently | 1 of 21, then 6 of 30 |

The first four were found while adjudicating disagreements between labelers,
which is worth stating plainly:
they were found by people arguing about prose, not by a test and not by a reading of the extractor.
A corpus finds the classes its material contains.
These four are what 376 boundaries of unseen prose contained.

## Governing constraint: there is no holdout

The bundle was opened, scored, and spent.
Its three sources have been read, and reusing them would measure memory rather than generalization.

That constraint decides the order of everything below, and it is not negotiable by convenience:

- **A never-flag rule can only remove findings.**
  Tasks 1 to 4 add cases where the extractor stops calling something prose.
  They cannot invent a false positive, and the calibration floors catch any recall they cost.
  These ship against the corpus we already have.
- **A change to the line-ender test adds findings.**
  Task 5 makes the detector report boundaries it currently passes over.
  Only one set can tell a correct new finding from a new false positive,
  and that is prose nobody tuned against.
  Task 5 is therefore **written** before Task 6 and **shipped** after it.

That distinction is not pedantic, and getting it backwards destroys a holdout.
The ledger binds a predicate digest.
Freeze first and tune afterwards, and the bundle refuses to open for the reason it should:
a tuned predicate needs a new holdout.
So the order is one order, and every task below assumes it:

```
Tasks 1-4        repair the four false positive classes
Task 5, steps 1-3  write the recall repair, and stop
Task 6           freeze THAT predicate, then draw, label, seal, score
Task 5, step 4   ship it, or withdraw it, on what Task 6 measured
```

One more rule, and nothing enforces it but this line:
the session that labels the holdout must not be a session that tuned the predicate.
Task 5's author and Task 6's labeler are different sessions.

## Global Constraints

- The core stays one file, Python 3.9+, stdlib imports only.
- Precision over recall stands.
  A miss is acceptable; a false positive is a bug.
- Every task ends green: `python3 -m pytest tests/ -q`,
  plus `bun test adapters/opencode/` when the adapter changed.
- Every task that changes what `check` returns must leave the calibration floors intact,
  or lower them explicitly in `manifest.lock` with a reason.
  Silence is the failure this rule exists to prevent.
- No task may be validated by the corpus it was tuned on.

## Group 1 — The four false positive classes

Each is one never-flag class, each ships with a fixture, and each is mutated afterwards.

### Task 1: Commented-out code in a doc comment

**Class:** contract

**Files:**
- Modify: `scripts/check_linefeeds.py`
- Modify: `tests/fixtures/`, `tests/test_precision.py`

The holdout's only false positive, at `helix:examples/replay/main.go:215`.
A doc comment carries a worked example written as line comments rather than as an indented block,
so the indented-example rule never sees it:

```go
// Connect to NATS with JetStream
// nc, err := nats.Connect("nats://localhost:4222")
// if err != nil {
//     log.Fatalf("Failed to connect: %v", err)
// }
// defer nc.Close()
```

The closing brace and the line after it became a boundary, and the detector called it a wrap.

- [x] **Step 1:** Reproduce it as a fixture before changing anything.
      The fixture is the holdout's shape, not the holdout's text.
- [x] **Step 2:** Decide the rule from the material rather than from taste.
      Candidates worth measuring against the compliant corpus:
      a content line that is bare code punctuation,
      a line holding an assignment or call operator,
      or a run of such lines rather than one line alone.
      Prefer the rule that removes the class and touches the fewest labeled true violations.
      Measured against the 718 labeled units:
      bare code punctuation removes the class and costs nothing,
      while an assignment-or-call test costs six labeled true violations —
      prose naming `AddStream()`, `Events()`, and `NewInProcessPair(WithLayout)`.
      The narrow rule was taken.
- [x] **Step 3:** Check the calibration floors and record any recall the rule costs.
      No frozen status moved, so no floor changed.

**Acceptance:** the fixture is silent, the floors hold or their loss is recorded,
and removing the rule turns a named test red.

### Task 2: A Markdown table row that does not start with a pipe

**Class:** contract

**Files:**
- Modify: `scripts/check_linefeeds.py`
- Modify: `tests/fixtures/markdown/`, `tests/test_precision.py`

The table rule reads `stripped.startswith("|")`.
GFM lets a row omit its leading pipe, and `rust-rfcs` does:

```markdown
`fn get(&self, &K) -> Option<&V>` | `HashMap`, `TreeMap`, `TrieMap`
`fn get_mut(&mut self, &K) -> Option<&mut V>` | `HashMap`, `TreeMap`
```

Both rows reached the detector as prose, and consecutive rows became a boundary.

- [x] **Step 1:** Fixture first, with a leading-pipe table beside a pipe-less one.
- [x] **Step 2:** Recognize the table by its delimiter row rather than by the first character,
      and skip the block it opens.
      A delimiter row is the only part of the syntax that cannot be confused with prose.
      A pipe is required in the delimiter row as well,
      so a setext underline still underlines rather than opening a table.
- [x] **Step 3:** A table inside a blockquote must behave the same way,
      since the marker now comes off before the structural tests.

**Acceptance:** both table shapes are silent, quoted and unquoted,
and a paragraph that merely contains a pipe is still checked.

### Task 3: A second licence block in one file

**Class:** contract

**Files:**
- Modify: `scripts/check_linefeeds.py`
- Modify: `tests/fixtures/`, `tests/test_precision.py`

`license_header_extent` returns the extent of the **leading** comment region.
A generated file can carry a second copyright block further down,
and `client_golang:exp/api/remote/genproto/v2/symbols.go` does.
Everything past the first block is judged as prose,
including "you may not use this file except in compliance with the License."

The calibration side recorded the same class from the other direction:
a licence header reached the sampling frame because the enumerator did not apply the cut the checker applies.
This is that defect's other half.

- [x] **Step 1:** Fixture with two licence blocks separated by code.
- [x] **Step 2:** Skip any comment paragraph carrying a licence marker, wherever it sits,
      rather than only the leading region.
      Keep the leading-region cut as well: it covers blocks whose first line carries no marker.
- [x] **Step 3:** Confirm the sampling enumerator and the checker still agree,
      since `_license_cut` in the harness mirrors this rule.
      The mirror is gone: both cuts live in `without_license_text`,
      and the harness calls it rather than reproducing it.

**Acceptance:** both blocks are silent, prose between them is still checked,
and the harness and the checker cut the same lines.

## Group 2 — The recall hole, and the instrument it needs

### Task 5: A line ending in inline markup

**Class:** design

**Files:**
- Modify: `scripts/check_linefeeds.py`
- Modify: `tests/test_precision.py`, `tests/fixtures/`

Two samples, drawn from different projects and labeled in different rounds, agree:

| Sample | `wrap` recall where the line ends in inline markup |
|---|---|
| calibration | 1 of 21 |
| holdout | 6 of 30 |

The cause is in `OK_LINE_ENDERS`.
The backtick, the closing bracket, and the closing quote are all listed as legitimate enders,
so a line ending in a code span is never a wrap.
That exemption was never measured before this release, and it costs four fifths of the stratum.

The repair is not the emphasis peel.
That one strips a delimiter to reveal the punctuation behind it.
This one has to remove a **whole trailing code span** and then ask what stands before it,
which is a different operation and a riskier one:
a false positive appears wherever a line legitimately ends at a clause boundary
that happens to be followed by a code span.

- [x] **Step 1:** State the rule and its refutation case in this file before writing code.

**The rule.**
A code span that closes a line is removed whole,
and the line is then judged by what stood in front of it.
Nothing is removed when the span is the entire line:
code alone is not a clause, so there is no clause end to look for behind it.

**Its refutation case.**
A line that ends at a real clause boundary which happens to be followed by a code span.
`method: ` + a span is the shape:
the colon ends the clause, and it only becomes readable once the span is gone.
Removing the delimiter alone would expose whatever punctuation the code contains,
which is why the emphasis peel must keep leaving backticks alone.

- [x] **Step 2:** Build it against the compliant corpus, which is adversarial and cheap to consult.
      No file in it moved: eleven `wrap` findings before, eleven after.
- [x] **Step 3:** Measure it against the calibration corpus.
      Expect the frozen statuses to move from accepted miss to detected,
      and raise the floors deliberately rather than letting them drift up unremarked.
      Six moved, `wrap` recall went from 163 of 220 to 169 of 220,
      and every floor that rose was restated in `manifest.lock`.
      None of the 450 labeled non-violations started drawing a complaint.

      One floor was removed rather than raised.
      The `trailing_inline_markup=True` level now reports 7 of 21 instead of 1 of 21,
      and 7 of 21 carries an interval wider than the 15 points a published rate is allowed,
      so the level prints its counts and no rate.
      The stratum this repair targets is the one stratum that can no longer carry a floor,
      and the per-unit frozen statuses are what guard it in the meantime.

**What the material also showed, and what this task did not take.**
Seven of the 21 true violations in the stratum end in a closing parenthesis rather than a code span,
and all seven are still missed.
Five of those seven would be reported by peeling a trailing parenthetical the same way,
which would take the stratum from 7 of 21 to 12 of 21.
That is a second rule with a worse refutation case —
prose ends a sentence in front of "(see below)" constantly —
and widening the change now would widen what the next holdout has to adjudicate.
It is recorded here with a number so the decision can be made on evidence rather than taste.

**What the repair found in this repository, which is unlabeled evidence and counts as such.**
Six `wrap` findings appeared in the repo's own Markdown, all of them from this rule.
One was in an accepted decision record and is repaired,
because that file is in this plan's verification checklist.
The other five sit in `adapters/opencode/INSTALL.md`, two completed plans, and two research notes.
Every one of them reads as a genuine mid-clause break on inspection,
splitting a verb from what it acts on,
which is a precision signal of the same sign as the labeled measurement.
They are left alone deliberately:
reflowing five historical documents for a rule that may be withdrawn is churn either way.
Step 4 resolves them, in whichever direction it goes.

- [ ] **Step 4:** Stop here and hand over to Task 6.
      Steps 1 to 3 leave the repair written and the calibration floors restated.
      Task 6 freezes *this* predicate and scores it.
      Come back to ship it, or to withdraw it, on what that measurement says.

      The measurement now exists, and the session that made it may not decide this step.
      What it says is below;
      the decision belongs to a session that has not read the prose it was taken on.

**Acceptance:** the new holdout clears the floors this task raises,
and the false positive count on unseen prose does not rise.

**What the second holdout measured.**
386 boundaries, 772 records, opened once against the predicate frozen before they were drawn.

| | round 1 | round 2 | floor asked |
|---|---|---|---|
| `wrap` | 231 of 311, 74.3% | 219 of 276, 79.3% | 0.70 |
| `fused` | 81 of 100, 81.0% | 50 of 77, 64.9% | 0.68 |
| false positives | 1 of 331 | 3 of 402 | — |

Read against this task's acceptance, three things are true and they do not all point one way.

- **The floor this task raised was cleared.**
  `wrap` is the kind the repair changes, its floor rose two points to 0.70 on the strength of the repair,
  and unseen prose returned 79.3% against a first round that returned 74.3% on the same kind.
- **A floor this task does not touch was missed.**
  `fused` fell to 64.9%, and the loss is entirely in Markdown:
  25 of 47 against the first round's 66 of 79, while Go rose to 25 of 30.
  Nothing in the frozen predicate changes how a fused line is found,
  so the failure belongs to that heuristic rather than to what was under test.
  It is a finding of this round, not a verdict on this task.
- **The false positive count rose, and none of it is this repair.**
  All three are one class:
  Swift proposals write code blocks with HTML entities rather than fences,
  so the code reaches the prose stream and a closing brace reads as a severed clause.
  Not one false positive came from a line ending in a code span.

**Class:** design

**Files:**
- Modify: `tests/corpus/manifest.json`, `tests/corpus/holdout/`

The first holdout was spent scoring v0.4.1, which is what it was for.
Task 5 cannot be trusted without a second one, and neither can the next precision claim after it.

Three new sources are needed, chosen the way the first six were:
on line-length distribution, licence, and never having been checked by this tool.
Neither the calibration six nor the spent three may appear.

- [x] **Step 1:** Select and pin three sources, with the same composition split:
      one self-authored, one third-party code, one third-party Markdown.
      Record the measured wrapping column and the qualification for each, as before.
      `arloliu/parti` at column 72, `grpc/grpc-go` at 75, `swiftlang/swift-evolution` at 78,
      from three organizations none of the earlier six came from.
      The instrument behind those numbers is committed for the first time,
      because the first six were measured by a script nobody kept.
- [x] **Step 2:** Freeze the predicate **before** drawing, not after,
      and freeze the one Task 5 leaves behind rather than the one that exists today.
      The first round recorded the predicate digest by hand and got the ordering right by care.
      Care is not a mechanism.
      Make the seal script refuse to run when the ledger holds no freeze
      for the predicate it is about to seal.
      A bundle's freeze binds a ciphertext and cannot be written until the prose is drawn,
      so the ledger gained a record that names a predicate and nothing that has been read;
      the draw refuses without it and so does the seal.
- [x] **Step 3:** Draw, label with three model families, adjudicate, seal.
      387 boundaries from a population of 47,791, one of which carries a labeling defect;
      386 boundaries and 772 records went to the seal.
- [x] **Step 4:** State the floors before opening, from the calibration rates as they stand then.
      0.70 for `wrap` and 0.68 for `fused`,
      the lower end of the calibration interval for each kind against 169 of 220 and 31 of 37.
      They were stated before the sample was drawn rather than merely before it was opened.

**Acceptance:** a sealed bundle whose freeze record predates its own sample,
enforced by the tooling rather than by the operator's care.

**What preparing the round exposed, none of it scored.**
Every item below was found while drawing and labeling,
which is to say by the same means the first round found its four false positive classes:
people and models arguing over prose, rather than any test in this repository.

| What | Evidence |
|---|---|
| A `//go:build` directive above a block-comment licence header defeats the licence cut | the same header without the directives yields no boundaries and with them yields six |
| The generated-file test reads only a file's first five lines | four boundaries from protoc-generated Go whose `DO NOT EDIT` marker sits under the licence block |
| Source code reaches the prose stream from comment blocks and from Markdown written with HTML entities | 26 of the 117 referrals |
| A labeling family will not answer one particular unit | four independent runs, one with an enforced reply shape |

The first two are false positive classes of the same shape as Task 3's,
and both were left alone on purpose:
the predicate is frozen, and this session is the one that labeled the round.
Repairing either belongs to a session that has not read this prose.
