# v0.9 umbrella — fixes and team integration

**Status:** active.
Slice plans are written one at a time against this frame;
this file does not repeat what a slice plan will specify.

## Purpose and acceptance signals

v0.9 takes the kit from a single-machine guardrail to one a team can adopt,
and closes the repair gap that a column-wrapped codebase walks into on its first edit.

Four signals define done:

- A repository can run the checker in CI and read the result in its code host,
  without a human running a command.
- A `fused` repair carries the sentence it splits off,
  in the recipe and in what the hook delivers.
- The automatic-fix class is widened on evidence rather than on judgment alone.
- Real agent repairs are measurable, so a later widening can be scored instead of argued.

## What the spike settled

ADR-0007 deferred hook-side mutation "until adapters can force a file-view refresh."
That condition was tested on 2026-08-18 and is the wrong question.

No host exposes a forced refresh.
Claude Code documents none for `PostToolUse`,
Codex CLI's `PostToolUse` is observe-only,
and opencode's plugin API documents no cache invalidation.

The condition is the wrong one:
every host's editing primitive compares content rather than writing by line number.
Claude Code's `Edit` locates `old_string` in the file on disk,
and both Codex and opencode use context-bearing patches for models that support them.
A stale write therefore fails instead of landing.

Measured directly on Claude Code:
a file written through the agent, then rewritten outside its view,
rejects an edit built from the stale text with `String to replace not found in file`,
accepts one built from the new text,
and the host injects the changed content into the agent's context unprompted.
Codex follows from the patch format rather than from a test, and opencode is unverified.

What a writing hook actually costs is friction, not a silent overwrite:
the agent's next edit fails, and it must re-read and retry once per repair.

**Hook-side mutation stays deferred, and the reason changes.**
It is deferred because the delivered suggestion is the preferred path in ADR-0007,
because both paths need the same first piece of work,
and because writing a user's file is a larger intervention than this tool's governing constraint invites.
A record superseding ADR-0007 must state the tested condition,
and it must land before any plan under this umbrella proposes a writing path.

## Architectural frame

Settled by earlier records, restated here as constraints on every slice:

- The portable core stays one stdlib-only Python 3.9+ file,
  and hooks keep invoking it bare
  ([ADR-0004](../../decisions/0004-portable-core-and-repository-cli.md)).
  A serializer is a renderer over the diagnostic schema, not a second detector.
- Precision beats recall for `fused` and `wrap`.
  A missed finding is acceptable; a false positive is a defect.
- A widening of the automatic class is a claim about safety,
  so it is scored against labels rather than asserted
  ([ADR-0003](../../decisions/0003-precision-measured-against-labels.md)).
- `wrap` reaches hook feedback only on a line a blocking finding already holds
  ([ADR-0021](../../decisions/0021-a-withheld-finding-travels-with-the-block-it-shares-a-line-with.md)).
- The CLI contract must not leak Python details,
  keeping the port option in [ADR-0011](../../decisions/0011-go-port-gated-on-field-evidence.md) cheap to exercise.

## The four slices

Slices 2 through 4 each run the full established process:
plan, external review to zero blocking findings, execution, final review, scoped squash, fast-forward merge.

### v0.9a — the fused repair carries its tail

**Landed on `main` as `2c9d13a`.**
No plan is owed; the work is recorded in `CHANGELOG.md` under `[Unreleased]`
and belongs to this release.

A `wrap` now travels with a blocking finding on its line,
the skill and the AGENTS.md snippet state that the rejoin comes before the split,
and the blocking report names the delivered finding as direction rather than as a second repair.

### v0.9b — a suggestion that reaches the line below

The first half of the automatic-repair item, and the entry condition for the rest of it.

A suggestion today is a two-line replacement for its anchor line alone.
Over the pinned evidence base at `930bac9`,
306 of 893 lines carrying a `fused` carry a `wrap` as well,
so a suggestion confined to one line is wrong for a third of the population it would serve.

Scope:

- A suggestion shape that can absorb the line under its anchor.
- The widened automatic class, admitted on scored evidence rather than on argument.
- No path that writes a file.

Depends on v0.9d for the evidence that admits a class.
Build the shape first and widen second, or the widening has nothing to answer to.

### v0.9c — the checker runs in CI and reports where the team reads

The team-integration half, and the only slice that does not touch the detector.

The repository has no `.github` directory at all,
so this slice creates the CI surface as well as the serializers.

Scope:

- A GitHub Action wrapping the published package.
- SARIF and code-host annotations as renderers over the existing diagnostic schema.
- A decision, recorded, on which kinds a CI run may fail a build for.
  `wrap` withholding was written for an editing agent, and CI is a different reader.

Independent of every other slice.
It can be built first if a team needs it sooner than the repair work.

### v0.9d — a corpus of real agent repairs

The measurement slice, and what v0.9b's widening is scored against.

The corpus harness, manifest, holdout discipline, and reporting already exist under `tests/corpus/`.
What is missing is the population:
what agents actually did with a finding, rather than what the detector reported.

Scope:

- A population of repairs, elicited from agents given a finding the way the hook gives one.
- Labels that say whether the repair was correct, and where a wrong one went wrong.
- A floor a widening must clear, stated before the labels are read
  ([ADR-0008](../../decisions/0008-a-holdout-is-spent-by-being-opened.md)).

**Not a capture path, and the reason is measured rather than argued.**
This slice originally scoped a sanitized channel for repairs made in real sessions.
Over 219 first-parent commits, this repository's history holds at most **10** of them.
That count over-counts:
a deleted line and an unrelated rewrite both look like a repair.
Ten over-counted events cannot score anything,
so a capture channel cannot reach a scoreable population inside this release.
The entry condition is field volume rather than a better argument,
and `docs/ROADMAP.md`'s "Feedback persistence" entry says the same.
Recorded as [ADR-0023](../../decisions/0023-what-a-repair-corpus-measures.md).

## Ordering

- v0.9a is done.
- v0.9c is independent and may run at any time.
- v0.9d precedes v0.9b's widening, though v0.9b's shape work can start beside it.

The one ordering that must not be inverted is widening before measuring.
A class admitted on judgment is the failure this project's precision constraint exists to prevent.

## Out of scope for v0.9

- Hook-side mutation, for the reasons recorded above.
- More language profiles.
  Marginal value has flattened while the workflow gap has not.
- Any contract freeze.
  Those enter guarantees at v1.0.
