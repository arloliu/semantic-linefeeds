# v1.0 — Stable Contracts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ship v1.0.0, the release whose whole content is a promise:
the surfaces a user or adapter builds against stop moving without a major version.

This slice writes decisions and documentation, not detector code.
The one class of code change it may carry is a contract defect the audit surfaces —
a surface that would be wrong to freeze as it stands —
and any such change lands before the freeze record, never after.

## What v1.0 freezes

Eight surfaces enter guarantees.
The roadmap named six;
the audit that produced this plan found two more already shipped and relied on,
and a freeze that ignores a shipped surface freezes it by accident.

| Surface | Canonical statement today | Pinned by |
|---|---|---|
| CLI surface | `semlf` usage text; README | `tests/test_cli.py` |
| Config schema | README `.semlf.ini` section; `DETECTOR_SPEC.md` configuration section | config fixtures in the suite |
| Diagnostic schema | `DIAGNOSTIC_SCHEMA_VERSION = 2`; `DETECTOR_SPEC.md` | schema tests, `tests/test_diagnostics_golden.py` (diagnostic dictionaries; no serializer golden today, see Task 2) |
| Adapter API | `DETECTOR_SPEC.md` public entry points table; hook payload handling | payload replay tests, bun suite |

| CI integration | `action.yml` inputs and output; the gate semantics of ADR-0026; SARIF and annotation shapes from `cli/semlf/render.py` | `tests/test_ci_gate.py`, `tests/test_render.py` (structural today; goldens owed, see Task 2) |
| Distribution identity | `pyproject.toml` (package name `semlf`, console script, Python ≥ 3.9); `.pre-commit-hooks.yaml` hook id; `.claude-plugin/plugin.json` identity | `tests/test_packaging.py` (console target, floor), `tests/test_precommit_hook.py` (hook id); package name and plugin identity unpinned today, see Task 2 |

## What v1.0 does not freeze

Stating the exclusions is as load-bearing as stating the guarantees:

- **Detector judgment.**
  Which lines draw findings may change in any release;
  precision work continues under the same holdout discipline.
  The freeze covers the shape findings arrive in and the mapping from a produced kind to the configured gate result,
  not the findings themselves.
- **Message and excerpt wording.**
  This plan decides the open question rather than inheriting it:
  `message` is display text and may change in any release,
  and `excerpt` carries source-derived content, so it was never fixable text.
  `DETECTOR_SPEC.md` currently calls `message` a "Frozen human-facing explanation";
  that word is removed before the freeze record, as an audited pre-freeze contract change.
  What stays stable for SARIF and annotation consumers is structure:
  rule identifiers (the three kinds), levels, and field placement.
- **Experimental keys.**
  `experimental-wrap` (env and ini) is named experimental
  and stays outside the guarantee, explicitly, in the freeze record.
- **The install lifecycle's file layout.**
  What `install` writes where is versioned by the manifest and repairable by `doctor`;
  it is an implementation, not a contract.
  The identifiers a user types or pins are the contract,
  and those are the distribution-identity surface above.

## Constraints

- Keep changes small: every edit traces to settling a gate, filling a documented gap,
  or cutting the release.
- No new features, no detector-judgment changes, no hook-side mutation
  (deferred in `docs/ROADMAP.md` with its entry condition).
  The one exception is stated in the goal:
  a contract defect the audit surfaces may be corrected pre-freeze,
  and that exception covers any audited surface, the portable core included.
- The two open precision questions stay open;
  each already carries a named entry condition and neither blocks a contract freeze.
- Release notes are user-facing words: no ADR codes, no slice names, no process talk.
- Every commit passes lint and the self-hosting check on its touched Markdown —
  this is standing repository policy,
  restated here because the audit may produce several small commits before the release commit.

## Tasks

### Task 1 — Settle the Go-port gate in a superseding record

ADR-0011 requires settlement before v1.0 in either direction,
because the freeze removes the room a port would need to correct a contract it proves wrong.
ADR-0011 is accepted, and accepted records are immutable;
the settlement is therefore a new ADR that supersedes it, not an edit to it.

- [ ] **Step 1:** Assemble the evidence inventory the settlement cites:
  the collection channels (GitHub issues, field reports recorded in `docs/`),
  the cutoff date, and what each channel holds.
  Known at planning time, three recorded reports:
  the `--agentsmd` absolute-path complaint (packaging, resolved by the packaged CLI),
  the `.tmpl` invisibility report (extraction coverage, deferred with its entry condition),
  and the v0.8.0 over-long-repair report
  (detector and repair-feedback behavior,
  fixed by the long-advisory change recorded in `docs/plans/done/2026-08-16-detector-precision-fixes.md`).
  The GitHub issue tracker is enabled and holds zero issues.
  The settlement rests only on the narrower supported fact:
  no inventoried report identifies unavailable `python3` as a blocker.
  `doctor` prints the invoking machine's platform and Python version for a human to relay;
  it does not aggregate anything, so the inventory counts reports, not telemetry.
- [ ] **Step 2:** Write the settlement ADR, superseding ADR-0011:
  the gate is settled **closed** at v1.0 on that inventory.
  Python is the authoritative implementation at the 1.0.0 release;
  the frozen observable contract remains implementation-agnostic;
  a differential-proven port may later become the sole authority behind it,
  exactly as ADR-0011's acceptable shape describes,
  but can no longer adjust the contract it stands behind.
  Mark ADR-0011 superseded by the new record with a status line and pointer only,
  the supersede mechanism ADR-0016 established and ADR-0004, ADR-0014, and ADR-0015 already use.
- [ ] **Step 3:** Remove the settled-before-this-tag clause from `docs/ROADMAP.md`'s v1.0 section
  (the new ADR carries the record).

### Task 2 — Audit the eight surfaces before freezing them

The last release that can correct a contract without a major version is this one,
so each surface gets one pass answering:
is the implemented behavior the one we want to promise,
and does the canonical statement match the implementation?

- [ ] **Step 1:** Exit codes — build the mode-by-mode matrix from source, not from memory.
  Known at planning time, to be verified and completed:
  file and git modes return `0` clean-or-advisory-only, `1` on a `fused`/`wrap` violation
  and also on a read error;
  the Claude hook returns `2` on a delivered blocking finding,
  `0` on advisory-only output,
  and `0` on a malformed payload — fail-open is deliberate,
  because a hook must not block editing on its own malfunction;
  `render` returns `0` after rendering regardless of findings, `1` on unreadable input;
  `64` is bad usage across `semlf` and core modes.
  `scripts/ci_gate.py`'s own argv is internal —
  the Action invokes it with controlled arguments,
  so its argparse usage exit (`2`) is unreachable through the frozen surface
  and only its `--fail-on` validation (`64`) participates in gate semantics.
  The matrix covers file mode, the git modes, both hooks, `render`, `reflow`,
  `doctor`, and the lifecycle commands.
  Distinguish findings from operational failures where both use `1`;
  a genuine incoherence is a defect to fix now,
  but do not invent a cross-command taxonomy the shipped codes do not have.
- [ ] **Step 2:** CLI surface.
  Enumerate flags and modes from `cli.py` and core `main()`;
  confirm README documents each shipped mode and no undocumented mode exists
  that we would regret freezing by accident.
- [ ] **Step 3:** Config schema.
  Confirm the ini keys, their env-var precedence, and discovery rules in README and `DETECTOR_SPEC.md` match the implementation.
- [ ] **Step 4:** Diagnostic schema.
  Confirm `DETECTOR_SPEC.md` describes every field of schema version 2,
  including `suggestion.replaces` and the withholding-classes surface,
  and apply the message-wording decision:
  "Frozen" comes off the `message` row, with the structural stability statement in its place.
- [ ] **Step 5:** CI integration.
  `action.yml` documents `fail-on` as two values while the gate accepts more —
  one grammar must win before it freezes.
  The implemented grammar, stated exactly:
  a comma-separated list whose segments are whitespace-trimmed and whose empty segments are ignored,
  which must leave at least one token,
  and whose every token is `fused` or `wrap`;
  duplicates and either order are tolerated.
  Freeze that grammar as written —
  a lenient parse is a coherent contract, and tightening it would break nobody for no gain —
  and align `action.yml`'s input description and the gate's error message to say it.
  Pin the boundary forms with tests:
  `wrap` alone, `wrap,fused`, duplicates, embedded empty segments,
  a whitespace-padded token,
  and the all-empty value rejected with `64`.
  Audit the remaining inputs, the `sarif-file` output, annotation commands,
  and the SARIF shape against source and goldens.
- [ ] **Step 6:** Distribution identity.
  Confirm package name, console script, Python floor, pre-commit hook id,
  and plugin identity are each stated where a user will look.
- [ ] **Step 7:** Adapter API and suppression syntax.
  Confirm the public entry points table and the suppression forms are current.
- [ ] **Step 8:** Recast the exact-message assertions in `tests/test_frozen_contract.py`:
  message text is display-only under this freeze,
  so those checks become deliberately updateable characterization assertions,
  the module's moving-one-byte-turns-this-red wording goes,
  and the structural and kind assertions stay frozen.
- [ ] **Step 9:** Add the contract pins the table names as owed:
  a golden or exact structural test for SARIF and annotation output,
  a test pinning the Action's input names, defaults, and `sarif-file` output,
  a pin on the PyPI project name,
  and a pin on the plugin manifest's name.
- [ ] **Step 10:** Write down the audit outcome per surface —
  clean, documentation gap, or contract defect —
  and fix what it found (gaps in Task 3's docs work; defects as their own commits).

### Task 3 — The freeze record and the documentation it requires

- [ ] **Step 1:** Write the freeze ADR:
  the eight guaranteed surfaces and where each canonical statement lives,
  what a breaking change to each looks like and that it costs a major version,
  and the exclusions above.
  Additive change is defined per surface, not by one slogan:
  a new optional diagnostic field, a new CLI flag or mode,
  a new Action input with a default, and a new ini key with a default are minor;
  a new diagnostic `kind` is **major**,
  because the kind set is closed
  and the bundled renderers index fixed maps by it and raise on an unknown value —
  calling it minor would require every consumer to tolerate unknown kinds first,
  and none does today;
  a raised Python floor, a renamed identifier, a removed or repurposed flag,
  and a changed field meaning are major.
  The remaining surfaces get their rule stated too:
  a new suppression directive form is minor and a changed meaning of an existing one is major;
  a new exit code for a new condition is minor
  and a changed meaning of an existing code is major;
  a new Action output is minor;
  the adapter API follows the diagnostic rules,
  since its entry points return the frozen shapes;
  distribution identity has no additive form — its changes are renames, and renames are major.
- [ ] **Step 2:** Add an exit-codes section to README carrying the Task 2 matrix
  (the one surface with no consolidated statement today).
- [ ] **Step 3:** Add a short compatibility statement to README:
  what a user may rely on from 1.x, in user-facing words.
- [ ] **Step 4:** Align `DETECTOR_SPEC.md` where the audit found drift.

### Task 4 — Cut the release

One recoverable sequence:
the repository reaches its finished state first,
the irreversible publish happens last,
and nothing after a failure point leaves a published artifact pointing at a repository that does not match it.

- [ ] **Step 1:** The finished-state commit(s):
  `CHANGELOG.md` gains its `[1.0.0]` section
  (the compatibility promise in user-facing words, plus anything the audit fixed);
  the version moves in its three places
  (`scripts/check_linefeeds.py`, `.claude-plugin/plugin.json`,
  `DETECTOR_SPEC.md`'s applies-to header);
  `docs/ROADMAP.md` drops the shipped v1.0 section per its own rule;
  this plan moves unchanged to `docs/plans/done/`.
- [ ] **Step 2:** Full gate on the finished tree:
  `python3 -m pytest tests/ -q`, `bun test adapters/opencode/`,
  lint, self-hosting check over every touched Markdown file.
- [ ] **Step 3:** Create the local `v1.0.0` tag on the finished commit and verify it.
- [ ] **Step 4:** Preflight, then `make release`
  (requires bun on PATH and the typed version confirmation):
  the tree is clean, `HEAD` is exactly what `v1.0.0` points at,
  and the version the build will publish matches the tag.
  Only then the PyPI upload — the one irreversible step.
- [ ] **Step 5:** Push branch and tag.
  A push failure after a successful upload is recoverable by retrying the push;
  nothing else needs undoing, which is why the upload waits for the tag and not the reverse.

## Ordering

Task 1 and Task 2 are independent; both precede Task 3.
Task 4 is last and strictly after everything.

## Out of scope

- Hook-side mutation, the Go port, and every deferred-list entry: each has an entry condition.
- The two open precision questions.
- The lifecycle follow-ups on record
  (the codex non-default-home detection gap and the install-redesign hardening list);
  none touches a frozen surface.
