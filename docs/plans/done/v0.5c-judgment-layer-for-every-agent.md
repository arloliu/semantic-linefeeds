# v0.5c Judgment Layer for Every Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL:
> Use superpowers:subagent-driven-development (recommended),
> or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every agent gets the judgment layer (ADR-0006):
a native Codex skill install, an upgraded fallback snippet,
hook feedback that carries an exact suggested replacement
and names the skill only when it exists,
and one bounded disagreement rule everywhere.
Skill uninstall stays out of scope — the roadmap assigns removal to `uninstall` in v0.6.

**Architecture:** All core changes stay in `scripts/check_linefeeds.py`.
`format_findings`'s frozen bytes stay frozen:
new behavior enters through a default-preserving keyword (`skill_hint=True`)
and through append-only additions inside `deliver`,
never by changing what today's callers already get without opting in.
The suggested replacement is maximally conservative:
every ambiguity — a second boundary, a code span anywhere on the line,
a closing delimiter between the terminator and the break, a stripped suppression carrier —
withholds the suggestion rather than guessing at it.
A missed suggestion costs nothing; a wrong one is a bug, per this repo's standing precision-over-recall rule.
Installer changes stay in `scripts/install.py`,
following the byte-compare-idempotent, refuse-without-`--force` pattern the opencode target already uses.

**Tech Stack:** Python 3.9+ stdlib only (`scripts/check_linefeeds.py`, `scripts/install.py`), pytest.

## Global Constraints

- The core stays one file: `scripts/check_linefeeds.py`, stdlib imports only.
- Precision over recall: a missed finding — or a missed suggestion — is acceptable;

  where this plan and an ADR disagree, the ADR wins.

### Task 1: A suggested replacement for automatic-class fused findings

**Files:**
- Modify: `scripts/check_linefeeds.py`
  (`_fused_suggestion` new, placed directly above `def diagnose`;
  `diagnose`'s per-line loop, from the trailing-carrier block through the fused branch)
- Modify: `docs/decisions/0007-fixability-classes.md` (append an Amendment section)
- Test: `tests/test_diagnostics.py` (append)

**Interfaces:**
- Consumes: `FUSED_RE` (module constant), `re` (stdlib, already imported).
- Produces: `_fused_suggestion(prose, raw, match) -> {"lines": [str, str]} | None`.
  A fused finding dict gains a `"suggestion"` key only when a suggestion was computed
  **and** the line's trailing suppression carrier (if any) was not stripped this iteration;
  the key is absent — never `None` — otherwise.
  `check()`'s tuple projection is unaffected:
  it already discards every dict key besides `line`, `kind`, `message`, `excerpt`.
  `--json` passes `"suggestion"` through as an additive optional key;
  `DIAGNOSTIC_SCHEMA_VERSION` stays `1`,
  because the key is optional, absent when not computed,
  and no existing consumer reads it —
  the same additive-field contract the schema's own docstring already claims for a breaking change,
  applied here to a strictly additive one.

**Design — maximal conservatism, not a new span engine:**
A suggestion is computed only when **all** of the following hold.
Any one failing means no suggestion, never a guess:

1. `FUSED_RE` finds **exactly one** match in `prose` (via `finditer`).
   A second boundary on the same line makes the split ambiguous.
2. The character **immediately** before the match's separating whitespace run is `!` or `?`.
   "Immediately" is exact:
   a closing quote, bracket, parenthesis, or emphasis mark sitting between the terminator and the space withholds the suggestion, full stop, rather than trying to move that delimiter across the break.
   This is stricter than "detect the delimiter and reattach it correctly";
   withholding is the conservative answer a slice without a real protected-span engine can defend.
3. The whitespace run itself is **exactly one ASCII space**, nothing else.
   `FUSED_RE` accepts any `\s+` run,
   so a tab, a doubled space, or a non-breaking space all still produce a finding,
   but none of them is safe to echo verbatim onto a second suggested line —
   a tab can turn Markdown prose into indented code,
   and every one of them is a sign the source is not the plain single-space-separated shape this task can reconstruct.
   Anything but one literal space withholds.
4. `prose` contains **no backtick, no `<`, and no `>` anywhere on the line** —
   not only near the match.
   The backtick rule kills every inline-code-span shape wholesale.
   The `<`/`>` rule kills every inline-HTML shape the same way:
   an inline HTML tag with a fusable-looking attribute value is still ordinary prose to the
   Markdown extractor as long as the line itself does not start with `<`,
   `FUSED_RE` can still match inside a quoted attribute,
   and there is no cheap, precise way this slice can tell "inside a tag" from "plain text"
   without a real markup parser (Step 1's mutation test spells out the exact fixture).
   Both rules are blunter than "is the split point inside the span/tag",
   and deliberately so:
   this slice has no general protected-span checker to answer that question precisely,
   so each rule declines the *whole* class of lines that could raise it, not just the matched region.
5. `raw.count(prose) == 1`, so `raw.find(prose)` locates the judged text unambiguously
   and the surrounding prefix/tail can be reattached to both halves.
6. The **prefix**, `raw[:idx]` where `idx = raw.find(prose)`,
   matches `^[ \t]*(?:(?:#|//|;|>)[ \t]*)*$` — whitespace plus zero or more repeatable line leaders
   (`#`, `//`, `;`, or a blockquote `>`), each optionally followed by more whitespace.
   A prefix built only from repeatable leaders can be safely duplicated onto the second suggested line, because doing so does not change what kind of line it is.
   A list marker (`-`, `1.`), a docstring's opening `"""`, or a block comment's opening
   `/*` fails this whitelist and withholds, because duplicating any of those turns one structural element into two, or leaves a syntax construct half-closed (see the Step 1 reconstruction tests).
   `*` is deliberately **not** on this whitelist, even though it is also a legitimate block-comment continuation marker (`" * next line"` inside a `/* ... */` block).
   The Markdown extractor treats a leading `*` as a list-item bullet
   (`LIST_ITEM_RE`, `scripts/check_linefeeds.py:137`) and strips it from `prose` while keeping it in `raw`, exactly like `-`; a whitelist that admitted `*` would duplicate
   that bullet and turn one list item into two, the same wrong-suggestion failure the hyphen case exists to exclude.
   Losing the suggestion on a genuine block-comment continuation line is an acceptable missed suggestion; splitting a list item in two is not — precision over recall applies to the prefix whitelist exactly as it does everywhere else in this design.
7. The **tail**, `raw[idx + len(prose):]`, matches `^[ \t]*$` — trailing whitespace only,
   nothing else.
   A one-line docstring's closing `"""` or a one-line block comment's closing `*/` lands here and fails; nothing may move across the break, so those shapes withhold too
   (usually in addition to already failing the prefix check above).
8. `raw` was **not** produced by stripping a recognized trailing suppression carrier this iteration
   (`scripts/check_linefeeds.py:961`, the `trailing_carrier(...)` block inside `diagnose`).
   A stripped carrier is user-authored text the two-line `{"lines": [...]}` shape has nowhere to put back,
   so the safe answer is no suggestion —
   this is a `diagnose`-level guard, not something `_fused_suggestion` itself decides (see Step 3).
9. `raw` contains no `\r`.
   Every entry path already guarantees this before `raw` is ever produced,
   so this is a belt worn over an already-fastened suspender, not a load-bearing check.
   `--file` mode opens files with `open(path, encoding="utf-8", errors="replace")`
   (`scripts/check_linefeeds.py:1542`),
   and the hook snapshot reader opens them with `open(path, encoding="utf-8")`
   (`scripts/check_linefeeds.py:1269`).
   Neither passes `newline=""`,
   so Python's universal-newlines mode already translates `\r\n` and bare `\r` to `\n` before either function's `text` variable exists.
   A Claude or Codex hook payload's `new_string`/`content`/patch text arrives through
   `json.load(sys.stdin)` instead of a file open,
   so it can in principle carry a literal `\r` decoded from a JSON escape sequence.
   But every extractor that ever produces a `raw` line calls `text.splitlines()` on the **whole** input first
   (`prose_lines_markdown`, `scripts/check_linefeeds.py:502`;
   `prose_lines_code`, `scripts/check_linefeeds.py:664`),
   and `str.splitlines()` recognizes every line boundary Python defines as a terminator —
   LF, CRLF, bare CR, and the Unicode separators including U+2028 —
   and never includes any of them in the yielded line
   (`_line_range`'s docstring already documents this, `scripts/check_linefeeds.py:906`).
   So `raw` cannot carry an embedded `\r` (or a bare Unicode line separator) on any current entry path;
   the check stays only so a future entry path that skips `.splitlines()` fails safe instead of silently mis-rendering a suggestion.

Because the terminator must sit with **zero** characters between it and the whitespace run (condition 2),
and that whitespace run is always exactly one space (condition 3),
the cut point is always `match.start() + (index of that whitespace run)`.
There is no separate "closing punctuation" pattern to match and no risk of moving a delimiter across the break,
since a line with one in that position never reaches construction at all.

**The suggestion's contract (ADR-0007 amendment):**
The suggestion replaces the single inter-sentence ASCII space with a line break followed by the repeated line leader (the reconstructed `prefix`, duplicated onto the second line);
outside that one insertion the bytes are identical to the source line the finding anchors on.
Concretely: `line1 + " " + line2[len(prefix):] == raw`
(`test_fused_suggestion_byte_identity_holds_with_a_duplicated_prefix` below tests this across an indented, a `#`-comment, and a `> `-blockquote case).
It is a suggestion the agent applies with its own editor on its next edit —
ADR-0007's stated preferred delivery — never a hook-side mutation of the file,
and this task never reads or writes a byte of the file itself.
ADR-0007 as originally written does not distinguish that delivery path from the deferred hook-side mutation path when it states the newline-style and content-hash clauses,
so this task amends it (Step 4 below) to say so explicitly:
those clauses continue to bind whichever path **writes** the file,
which today is only the still-deferred hook-side mutation — a path this delivery is not.
This delivery's own contract is narrower and exact on its own terms:
the insertion point and the inserted text (one line break, one repeated prefix,
one dropped inter-sentence space) are precisely defined, and nothing else about the two lines is claimed — in particular, this plan makes no claim about what an agent's own editor does with newline style when it applies the suggestion, since nothing in this delivery path controls that editor.

```python
# The repeatable line leaders a suggestion's prefix may be built from:
# whitespace, then zero or more of #, //, ;, or a blockquote >, each
# optionally followed by more whitespace.  A list marker, a docstring's
# opening quotes, and a block comment's opening /* all fail this
# whitelist on purpose.  * is deliberately absent even though it is
# also a legitimate block-comment continuation marker: the Markdown
# extractor also treats a leading * as a list bullet and strips it from
# prose while keeping it in raw, so admitting it here would duplicate
# that bullet and split one list item into two.  Losing the suggestion
# on a real block-comment continuation is the accepted missed-
# suggestion cost of closing that hole.
_SUGGESTION_PREFIX_RE = re.compile(r"^[ \t]*(?:(?:#|//|;|>)[ \t]*)*$")

# The suggestion's tail may carry only trailing whitespace; nothing may
# move across the break.
_SUGGESTION_TAIL_RE = re.compile(r"^[ \t]*$")


def _fused_suggestion(prose, raw, match):
    """A two-line suggested replacement for an automatic-class fused finding, or None.

    Maximally conservative rather than a real protected-span engine: no
    suggestion unless FUSED_RE matches exactly once, the terminator sits
    with nothing between it and a single ASCII space, `prose` has no
    backtick/`<`/`>` anywhere on the line, `raw` contains `prose`
    exactly once, and the prefix/tail around `prose` in `raw` both pass
    the structural whitelist above.  Any closing quote, bracket, paren,
    or emphasis mark between the terminator and the space withholds the
    suggestion instead of trying to reattach it.
    `raw` cannot carry an embedded `\\r` on any current entry path
    (every extractor reaches it through `str.splitlines()`), so that
    check is a belt over an already-fastened suspender, kept for a
    future entry path that might skip it.
    """
    if "\r" in raw:
        return None
    if len(list(FUSED_RE.finditer(prose))) != 1:
        return None
    if "`" in prose or "<" in prose or ">" in prose:
        return None
    if raw.count(prose) != 1:
        return None
    text = match.group(0)
    ws = re.search(r"\s+", text)
    if ws.group(0) != " ":
        return None
    terminator = text[ws.start() - 1]
    if terminator not in "!?":
        return None
    idx = raw.find(prose)
    prefix = raw[:idx]
    tail_text = raw[idx + len(prose):]
    if not _SUGGESTION_PREFIX_RE.match(prefix) or not _SUGGESTION_TAIL_RE.match(tail_text):
        return None
    cut = match.start() + ws.start()
    p1 = prose[:cut]
    p2 = prose[cut:].lstrip(" ")
    return {"lines": [prefix + p1, prefix + p2 + tail_text]}
```

```python
def _looks_like_the_skill(path):
    """Whether path is a readable file whose frontmatter names this skill.

    A bare existence check, or a bare substring search, would send an
    agent to load a corrupt or unrelated file at the same path -- a
    file whose *body* happens to mention the skill's name is not the
    skill.  Requiring the exact name line to sit inside an opened and
    closed `---` block rules that out without parsing YAML.

    Reads 1025 bytes so a closing delimiter can never be confused with
    end of file: if fewer than 1025 came back, the buffer already is
    the whole file, so a trailing `\\n---` at the end of it is a true
    close.  If exactly 1025 came back, the file continues past the
    probe, so only a closing delimiter followed by `\\n` fully inside
    the first 1024 decoded characters counts -- the 1025th byte itself
    never enters the match, since its only job is telling truncated
    from whole.
    """
    try:
        with open(path, "rb") as f:
            head = f.read(1025)
    except OSError:
        return False
    truncated = len(head) == 1025
    if truncated:
        head = head[:1024]
    try:
        text = head.decode("utf-8")
    except UnicodeDecodeError:
        return False
    if not text.startswith("---\n"):
        return False
    body = text[4:]
    close_pattern = r"\n---\n" if truncated else r"\n---(?:\n|$)"
    close = re.search(close_pattern, body)
    if not close:
        return False
    frontmatter = body[:close.start()]
    return "name: semantic-linefeeds" in frontmatter.splitlines()


def _judgment_layer_present(transport):
    """Whether hook feedback may tell the model to load a judgment-layer skill.

    Claude Code always has one: the skill ships inside the plugin that runs
    this hook.
    Codex has one only when a candidate at either location Codex resolves
    standalone skills from (ADR-0006) reads back as this skill: a
    repository `.agents/skills` directory, or `$HOME/.agents/skills` when
    `$HOME` actually resolves to something (`os.path.expanduser("~")`
    returns its input unchanged when it cannot).
    """
    if transport == "claude":
        return True
    if transport == "codex":
        candidates = [os.path.join(".agents", "skills", "semantic-linefeeds", "SKILL.md")]
        home = os.path.expanduser("~")
        if home != "~":
            candidates.append(os.path.join(home, ".agents", "skills",
                                            "semantic-linefeeds", "SKILL.md"))
        return any(_looks_like_the_skill(p) for p in candidates)
    return True
```

```markdown
## Semantic linefeeds

When writing or editing prose in code comments, doc comments, docstrings, or Markdown:
break lines by meaning, not by column.
One sentence per line;
a sentence longer than the configured limit (default 120 chars) splits only at a real clause boundary
(`;`, `:`, `—`, or a conjunction where both sides stand alone).

A conjunction (`and`, `but`, `so`) or relative pronoun (`which`, `that`, `where`) is a boundary only when both sides could stand alone as a complete sentence.
A compound subject or object does not split:
"depends on X and Y" has no boundary at "and".

Never break: URLs; compiler and lint directives; generated-file headers;
javadoc/JSDoc/doxygen tag lines; license headers; fenced code and `<pre>` blocks;
doctest lines; Markdown link reference definitions; and table rows.
Never rewrap existing text you are not otherwise editing.

Judge a finding before rewriting.
A believed false positive, or a finding that survives one repair attempt, ends the loop:
stop retrying and surface the disagreement to the user instead of rewriting correct prose again.
An agent never adds a suppression directive on its own authority: if you judge a finding to be a false positive, leave the text as it is and surface the disagreement to the user instead.
```
