# v0.5a — Span Model and Diagnostic Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL:
> Use superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every finding becomes a diagnostic carrying anchor, evidence, and ownership ranges,
`diagnose(text, path, spans=None)` is the rich entry point that restricts reporting to owned diagnostics,
and a versioned JSON schema replaces the ad-hoc `--json` shape,
with text as one renderer over the same structure.
`check(text, path)` keeps its exact two-argument tuple contract as a projection over `diagnose`.

**Architecture:** The walk inside today's `check` moves into `diagnose` unchanged;
`check` becomes a thin projection over it,
so the corpus harness, the frozen-predicate replay, and all existing tests keep their contract.
Ranges are half-open code-point offsets into the checked text,
built from a per-line offset table.
Token location that cannot find its text exactly once produces a diagnostic **without** an ownership range;
such a diagnostic reports normally when no spans are given
and is withheld whenever spans are supplied,
because guessing an owner would let an unrelated edit resurrect an unchanged boundary.

**Tech Stack:** Python 3.9+, stdlib only, one file: `scripts/check_linefeeds.py`.

## What ADR-0005 fixes, restated operationally

- **anchor** — where the diagnostic is displayed: the raw line it points at.
- **evidence** — all context used to establish it:
  for `wrap` both lines of the boundary, otherwise the anchor line.
- **ownership** — the accused causal text itself:
  for `wrap` the upper prose line's terminal token through the lower line's opening token;
  for `fused` the located match extended through the right-hand opening token;
  for `long` the prose as it sits in the raw line, markers excluded.
- A diagnostic is reported under spans **only**
  when its ownership range touches a changed span or boundary.
- **Touching:** two non-zero half-open ranges touch only when they strictly overlap,
  sharing at least one code point;
  an edit that stops exactly where the accused text begins changed nothing inside it,
  and reporting there would be a false positive.
  A **zero-width boundary** touches a range when it lies anywhere on it,
  edges included,
  because a deleted newline leaves no after-state text
  and its point must be able to own the boundary it created.
- **Degraded location:** when a token cannot be found exactly once in its raw line,
  the diagnostic carries `ownership: None` with `ownership_basis: "degraded"`.
  It reports normally when `spans is None`,
  and is withheld whenever spans are supplied —
  a suppressed true finding is the acceptable miss,
  an unrelated-edit report is the bug.
  Known degraded classes today: peeled emphasis terminals (`Use *`value`*` peels to `*`),
  repeated tokens, and duplicated fused substrings.
  Recovering exact ownership for them via a prose-to-raw offset map is deliberately deferred
  (see Out of scope);
  `ownership_basis` makes the degraded rate observable in the meantime.
- Changed spans are half-open after-state ranges plus zero-width boundaries,
  each recording `mapping: "exact"` or `"degraded"`.
  In this slice the filter treats both mappings identically;
  what a degraded mapping forfeits (falling back to payload-only checking)
  is the hook's decision, wired in Plan B per ADR-0005.
- The rich entry point is `diagnose(text, path, spans=None)`;
  `check(text, path)` stays two-argument.
  ADR-0005 and the roadmap still write this contract as `check(text, path, spans)`,
  so Task 7 amends both to name `diagnose`,
  keeping the accepted documents and the code in agreement.

### Task 1: Span normalization and the touching rule

**Files:**

**Interfaces:**
- Produces: `normalize_span(span) -> dict` accepting
  `{"start": int, "end": int}` or `{"at": int}` plus optional `"mapping"`,
  returning `{"start": int, "end": int, "mapping": "exact"|"degraded"}`.
  Anything else — a non-mapping value, unknown keys, mixed shapes, missing keys,
  non-integer or negative offsets, a backwards range, an unknown mapping value —
  raises `ValueError`.
- Produces: `touches(rng, span) -> bool` over two normalized ranges:
  strict overlap (`max(starts) < min(ends)`) when both ranges are non-zero,
  closed comparison (`max(starts) <= min(ends)`) when either side is zero-width.
  Adjacent non-zero ranges therefore do **not** touch;
  a zero-width boundary on a range's edge does.

```python
# A changed span is where an edit landed in the after-state text.
# Half-open over code points, except that a deleted newline leaves no
# after-state text at all, so a boundary is carried as a zero-width span.
# "mapping" records whether the adapter located the edit exactly or fell
# back to something coarser; the hook, not the core, decides what a
# degraded mapping forfeits.
def normalize_span(span):
    if not isinstance(span, dict):
        raise ValueError(f"span must be a mapping: {span!r}")
    unknown = set(span) - {"at", "start", "end", "mapping"}
    if unknown:
        raise ValueError(f"span carries unknown keys: {span!r}")
    if "at" in span:
        if "start" in span or "end" in span:
            raise ValueError(f"span mixes 'at' with a range: {span!r}")
        start = end = span["at"]
    elif "start" in span and "end" in span:
        start, end = span["start"], span["end"]
    else:
        raise ValueError(f"span needs 'at' or 'start' and 'end': {span!r}")
    for offset in (start, end):
        if isinstance(offset, bool) or not isinstance(offset, int):
            raise ValueError(f"span offsets must be integers: {span!r}")
    if start < 0 or end < start:
        raise ValueError(f"span is not a forward range: {span!r}")
    mapping = span.get("mapping", "exact")
    if mapping not in ("exact", "degraded"):
        raise ValueError(f"span mapping must be exact or degraded: {span!r}")
    return {"start": start, "end": end, "mapping": mapping}


def touches(rng, span):
    """Strict overlap for ranges; a zero-width boundary touches on an edge.

    Two half-open ranges must share a code point: an edit that stops
    exactly where the accused text begins changed nothing inside it,
    and reporting there is a false positive.  A deleted newline leaves
    no after-state text at all, so a zero-width boundary counts when it
    lies anywhere on the range, edges included.
    """
    lo = max(rng["start"], span["start"])
    hi = min(rng["end"], span["end"])
    if rng["start"] == rng["end"] or span["start"] == span["end"]:
        return lo <= hi
    return lo < hi
```

```python
def line_offsets(text):
    """Code-point offset of each 1-based line's start, with an end sentinel.

    Partitioned with str.splitlines, the same call the extractors
    number lines with, so every terminator it recognizes (LF, CRLF,
    bare CR, the Unicode separators) starts a new line in both places.
    """
    offsets = [0]
    for line in text.splitlines(keepends=True):
        offsets.append(offsets[-1] + len(line))
    return offsets


def locate_in_line(text, offsets, lineno, needle):
    """The absolute range of a needle that occurs exactly once in a line.

    Prose is the raw line with markers stripped, so a prose substring
    usually appears verbatim in the raw line.  Where stripping or
    repetition breaks that, the caller drops ownership entirely rather
    than guessing which occurrence was meant.
    """
    if not needle or lineno < 1 or lineno >= len(offsets):
        return None
    start, end = offsets[lineno - 1], offsets[lineno]
    line = text[start:end]
    first = line.find(needle)
    if first < 0 or line.find(needle, first + 1) >= 0:
        return None
    return {"start": start + first, "end": start + first + len(needle)}
```

Note `keepends=True` makes the offsets sum to `len(text)`,
so the final entry is always the sentinel and `offsets[lineno]` is valid for the last line:
`line_offsets("ab\ncde\n\nf")` ends `[..., 9]` and line 4 is `text[8:9]`.
The table length is always the line count plus one,
and empty text yields `[0]`.

    "message": str,                  # same message check() carries today
    "excerpt": str,                  # the prose line, untruncated

    "evidence": {"start": int, "end": int},    # wrap: both lines; else the anchor

- `check(text, path)` keeps its exact contract:
  `[(line, kind, message, excerpt), ...]`, sorted by line, built as

**Ownership per kind, exactly:**

- `fused`: the `FUSED_RE` match located verbatim in the raw line,
  extended right from the match's end to the next whitespace of **any** kind
  (`re.search(r"\s", ...)` bounded by the anchor's end, never a bare `find(" ")`,
  so a tab after the opening token ends ownership there).
  Locate failing (absent or ambiguous) gives `ownership: None`, basis `"degraded"`.
- `wrap`: from the start of the upper prose line's terminal token
  (last whitespace-delimited token of `line_ending(prev_prose)`, located in the upper raw line)
  through the newline to the end of the lower line's opening token
  (`first_word.group(0)`, located in the lower raw line).
  `line_ending` can peel a line down to empty or to a bare delimiter,
  and either token can be absent, ambiguous, or out of order in its raw line;
  every such case gives `ownership: None`, basis `"degraded"`.
- `long`: the prose located verbatim in the raw line,
  so indentation, quote markers, list markers, and comment syntax are **not** owned;
  locate failing gives `ownership: None`, basis `"degraded"`.

```python
def _line_range(text, offsets, lineno):
    """The raw line as a half-open range, its line terminator excluded.

    splitlines strips whichever terminator ends the line — LF, CRLF,
    bare CR, or a Unicode separator — so the range never accuses one.
    """
    start, end = offsets[lineno - 1], offsets[lineno]
    split = text[start:end].splitlines()
    content = split[0] if split else ""
    return {"start": start, "end": start + len(content)}
```

## Out of scope, deliberately

- Wiring spans into any hook, Edit/patch span mapping, `--staged` — Plan B,
  after ADR-0010 (the suppression contract, stateless single-line directives) is accepted.
- A prose-to-raw offset map carried through extraction,
  which would recover exact ownership for peeled emphasis terminals and repeated tokens instead of degrading them.
  `ownership_basis` makes the degraded rate observable;
  if it proves too lossy under spans, that map is the follow-up, not a widened guess.
- Suggested diffs, `SKILL.md` for Codex, `SNIPPET.md` upgrades, bounded disagreement — Plan C.
- Numeric `confidence` — excluded by the roadmap until observed rates support one.
- CRLF and Windows paths — scheduled for v0.6 across every adapter;
  until then `line_offsets` partitions with `str.splitlines` exactly as the extractors number lines,
  and `_line_range` excludes whatever terminator ends a line, both pinned by test.
